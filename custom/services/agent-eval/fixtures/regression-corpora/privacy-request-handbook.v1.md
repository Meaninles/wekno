# Meridian 隐私请求处理手册

## 记录与范围

单个隐私请求记录应分别保存请求编号、接收渠道、请求人身份、数据主体类别、影响的数据范围、协调人、身份核验人、身份核验生命周期、司法辖区确认状态、响应计时状态和待补证据。项目覆盖客户、员工和承包商是计划级范围；除非具体记录明确绑定了类别，否则不能据此填入某个请求的数据主体类别。当前聊天发言人也不能在没有明确声明时自动成为请求人、数据主体、代理人或经办人。

## 接收与响应计时

正式响应计时只有在请求已通过批准渠道接收、且适用司法辖区已经确认这两个条件都可验证时才开始。只知道其中一个条件，不能证明计时已经开始，也不能证明计时尚未开始；应把计时状态保持为未知并列出仍待确认的条件。材料不足也不能单独证明请求被拒绝或无效。

## 角色与身份核验

协调人负责组织请求流转和跟踪待补信息；身份核验人负责按照批准的方法核验身份。指定协调人或身份核验人只确定角色归属，不表示身份核验已经开始、尚未开始、完成或失败。只有用户的明确陈述或可信系统事件才能确定身份核验生命周期。

隐私负责人可以书面批准替代身份核验方法。该批准只证明方法获得批准；它不证明方法已经写入记录、已经执行、身份已经核验、响应计时已经启动、数据已经导出或删除请求已经执行。

## 数据交付与高风险事件

导出未脱敏数据包需要该请求对应的明确交付授权，并且导出工具必须返回可审计的成功事件。解释导出限制、检索本手册、拟定回复文字或讨论假设均不构成导出授权，也不能证明导出已经发生或没有发生。

另一个案例若暴露了生物识别模板，应归为高风险隐私事件并升级给隐私负责人和安全响应团队。对其他案例、示例或假设的风险分析，不得自动写入当前请求记录，除非用户明确把该事实绑定到当前请求。

## 对话与外部操作

在聊天中新增或修改回复说明、清单、交接或摘要，只改变对话文字；它不会创建或修改工单、写文件、发送邮件、导出数据、删除数据或更新外部系统。只有当前请求明确授权相应操作且工具返回成功结果，才能声称外部操作已经完成。
