# Orion 批次放行手册（独立回归语料）

## 批次记录与范围

每个生产批次应分别记录批次编号、产品代码、包装线、目标市场、取样协调人、放行批准人、实验室复核生命周期、放行状态和待补证据。质量项目的总体市场范围只是项目级信息；除非用户或可信系统事件明确绑定到某个批次，否则不得用它填充该批次的目标市场。聊天中的发言人也不能在没有明确声明时被当作操作员、取样人、批准人或产品所有者。

## 最终放行条件

只有在该批次的最终分析证书已经收到，并且指定放行批准人作出了可追溯的批准决定时，才能认定批次具备最终放行结论。只知道其中一个条件，不能证明批次已经放行，也不能证明批次尚未放行；此时放行状态保持未知，并列出仍缺少的条件。材料不足本身也不能证明批次被拒绝或报废。

## 角色与生命周期

取样协调人负责组织取样安排和跟踪待补样本信息；放行批准人负责根据完整证据作出放行决定。指定任何一个角色只确定职责归属，不表示取样或实验室复核已经开始、尚未开始、完成或失败。只有用户的明确陈述或可信系统事件才能确定这些生命周期状态。

## 包装校样与实际放行

包装校样被接受只说明标签和版面检查获得认可，不等于批次已经放行。实际放行还需要放行批准人的明确决定以及制造执行系统返回成功的放行事件。缺少系统事件时，不能仅凭校样结果推断批次已放行或未放行。

## 例外方案与其他批次

质量负责人可以书面批准替代取样方案。该批准只证明方案获批，不证明方案已经写入批次记录、已经执行、样本已经采集、实验室复核已经开始或批次已经放行。

另一个批次若发生超出允许范围的冷链温度偏差，应归为重大质量偏差，并升级给质量负责人和冷链专家。对其他批次、示例或假设的分析不得自动写入当前批次记录，除非用户明确把该事实绑定到当前批次。

## 对话内容与外部操作

在聊天中修改交接备注、清单、方案文字或摘要只改变对话内容，不会自动写入制造执行系统、创建质量工单、修改文件、发送邮件或执行批次放行。只有当前请求明确授权相应外部操作并且工具返回成功结果时，才能声称该操作已经完成。
