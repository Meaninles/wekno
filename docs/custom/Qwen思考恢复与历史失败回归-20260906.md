## 最新会话为什么没有输出

本地账号最新创建的会话是 `4e133918-214f-447b-b9b3-59ec079ff940`，标题为「整理茅台近期舆情并制作PPT」。

1. 前 10 次模型请求均正常产生结构化工具调用。搜索、行情和文章提取结果已成功回传，总计执行 17 次工具。
2. 第 11 次模型请求包含 29 条消息、22 个工具定义，输入为 54834 tokens。返回 `completion_tokens=8192`、`finish_reason=length`，仅有思考，没有答案和完整工具调用。该次思考没有 `<tool_call>` XML；本次证据不支持归因为旧解析器吞掉工具 XML。
3. `custom/services/general-agent/app/platform_runtime.py` 遇到这种未交付的终止结果会直接报错，不会把思考当作答案或可执行代码，也没有 SDK 那样的后续恢复循环。
4. SSE 和数据库中均记录 `model did not deliver a complete answer: finish_reason='length'`，消息已终止。因此缺失的是后端未生成的最终交付，不是已有最终答案被前端漏掉。

这里证实的是直接失败机制。没有单凭 token 耗尽就断言其深层原因仅为强度、上下文长度或工具描述。

## 工具调用中仍存在的情况

- **Qwen SDK 截断恢复**：两次模型终止均为 `max_tokens`、8192 输出 tokens；工具 JSON 只传到 `{"language":"python"` 或 `{"language":"shell"`，SDK 报 `InputValidationError`。这不是完整 JSON 被我们的工具 schema 拒绝，而是输出尚未完成。SDK 回传错误后，模型自行分六段写脚本，后续执行、11 页检查、`create_artifact` 和最终回答完成。
- **Qwen 平台协议缺少同等恢复**：收到 `length` 后直接终止。与 SDK 的处理不同，已由相同任务的真实记录及执行器源码确认。不能把“SDK 最终恢复”表述为工具调用全程没有问题。
- **技能入口试错**：Qwen SDK 的 `read_skill` 返回 `tool returned no result`，随后通过 `read_file` 读取实际 SKILL。两种 Qwen 运行方式都尝试读取不存在的可选 `runtime.conf`，随后定位实际 Python CLI 继续执行。这些错误没有阻止任务进入检索，但有额外调用成本；本轮未修改技能入口。
- **DS 代码试错**：SDK 生成的代码尝试了当前 PyMuPDF 不支持的字体参数，工具如实返回异常；模型随后修正并完成。没有复现历史 DS 接收图像 tool_result 时的网关 400。

检查流程和工具结果时另发现 PDF 字体子集化造成缺字、PPT 分红数字口径混用。按用户最新要求保留证据，不继续修改或用文档质量否定已经完成的调用链；也不将上述流程完成等同于内容全部准确。
