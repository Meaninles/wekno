# 智能体结构化引用与输出前过滤

实现位置：`eval` 工作树。知识问答、通用智能体等共用 AgentScope 最终提交链路。

## 模型输出

保留现有 `GenerateStructuredOutput` 和 `answer`，增加 `citations`：

```json
{
  "answer": "正文A。正文B。正文A。",
  "citations": [
    {"text": "正文A。", "source_ids": ["S1"]},
    {"text": "正文A。", "source_ids": ["S1", "S2"]},
    {"text": "正文B。", "source_ids": ["S3"]}
  ]
}
```

`text` 是从回答原样复制的连续正文，不是来源摘录。相同 `text` 合并为一项，ID 去重；只在正文第一次出现的位置之后插入引用。

`sourcerefs.StructuredOutputContract` 提供完整模板及构建步骤，并替换运行时旧的内嵌标签提示。业务工具的输出提醒也改为填写 `citations`。模型先写完整连贯正文，再在同一次最终提交中填写引用列表，不拆分生成正文，不追加审查、补齐或修复模型调用。

## 本轮完整来源

已有 `runs/budget` 控制请求返回 `run_id` 和 `current_run_sources`，运行时将其放入当次决策的 `runtime_budget` 系统消息 `[CURRENT_RUN_SOURCES]` 中。此列表按本轮后端 `RunRecord.References` 生成，不从历史回答提取，不受单次业务工具文本截断影响。

列表包含每个可用来源的 `id`、`title`、`chunk_id`；全部可用 ID 都保留。`id` 来自 `reference.metadata.citation_id`（如 `S7`），`chunk_id` 是原始来源定位值，两者不可混用。证据正文继续通过相应工具结果或来源文件提供；来源索引本身不能作为事实依据。

## 确定性过滤与发布

`sourcerefs.RenderStructuredCitations` 在后端持久化最终结果前运行：

1. 不完整、缺失或类型错误的引用列表/条目按空引用处理，单个错误 ID 不影响同项其他合法 ID。
2. 空 `text`、找不到精确正文锚点的条目丢弃，不做模糊匹配或真实性判断。
3. 删除不属于本轮注册表的 ID、非规范 `S…` ID，以及缺少证据正文或对应来源类型必需定位数据的 ID；一项全部 ID 无效时丢弃该项。
4. 相同 `text` 合并有效 ID 并去重；正文中多次出现时使用第一次。所有插入位置先计算，再从后向前插入 `<src id="S…" />`，避免偏移。
5. 实际引用之外的来源不进入最终消息 `references`；本轮完整注册表及原始模型提交检查点保留。最终结果保存过滤后的 `citations`。

模型不应在 `answer` 自行插标签。为防止绕过列表生成引用，渲染器清除正文中的引用协议标签（代码示例保留），只为过滤后的条目生成活动标签；普通正文不改写。全部引用被丢弃时照常发布正文，不触发模型重答。

验证接口保留候选正文，提交时统一过滤。重复提交同一候选会对照确定性结果返回原提交，处理响应丢失时的重试。Python 侧不发布候选 `answer_delta`，Go 回放也忽略它；用户正文通过最终 `result` 一次发布，工具进度仍可流式显示。

模型侧看见明确的数组/对象 schema，SDK 执行侧接收原始引用数据：这是为了避免 SDK 对错误引用格式自动发起模型修复。`answer` 的非空字符串与外层 JSON 结构仍须有效。

前端保持现有机制：根据正文中实际引用首次出现的顺序，从 1 连续编号。例如实际用到 `S1,S2,S7,S8,S4,S5`，显示为 `1,2,3,4,5,6`，无需使用全部来源。
