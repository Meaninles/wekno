# 内置智能体思考恢复改造与手工验收

本次只修改本地 eval 工作树和数据库，没有修改生产 WeKnora、网关或上游推理服务，没有发送真实模型问答请求。

## 本次落地

- 本地对话模型保留 **DeepSeek V4 Flash**、**Qwen3.8-27B**，Qwen 为全局默认；保留内置智能体原有默认模型和思考开关。调用仍使用已有网关路由 `DeepSeek-V4-Flash-Agent`、`Qwen3.8-27B-Agent`，没有新增模型别名、对照智能体或提高输出预算。
- 下线本地 5 个旧/对照模型和 15 个测试智能体，保留 9 个现有内置智能体。同步更新会话输入设置、知识库、衍生任务等配置中的旧 ID；历史问答、来源文件、已完成任务的模型记录和向量索引保留。
- 运行时上下文使用资源目录和原文文件：保留全部可见资源 ID、名称及当前选择，详细配置按需读取。没有根据问题关键词删减工具，没有改写用户问题。
- 超过 24,000 字符的工具结果保留完整原文，模型先看到 2,000 字符预览及读取入口。Go 使用本轮 `read_conversation` 归档，Python 使用工作目录原文文件。分页读取不会反复归档；引用标识、原始工具记录和图片继续保留。
- 两个 Python 适配器共用 `write_file`、`edit_file`：创建 UTF-8 文件、按当前文件 SHA256 和唯一匹配文本修改，也支持追加。过期哈希、覆盖已有文件、模糊匹配和越出工作目录会被拒绝。文档仍由原有代码执行、转换、检查和产物登记工具处理，模型自行选择操作步骤。
- 按协议识别输出截断或正常结束却没有回答，每次运行最多恢复一次；保留已完成的工具调用，不执行截断的参数，不把未完成正文当作成功答案。Go/平台适配器保留完整已完成消息并追加运行状态；Claude SDK 通过本次运行的原生会话记录恢复，沿用剩余工具轮次。网络错误、缺失终止事件、取消及轮次耗尽不会触发这类恢复。
- 桌面和移动端会在资源列表加载成功后处理已删除的智能体选择，移动端也会纠正已删除的模型选择。
- 本地 eval API 端口统一为 `8080`，修正旧 `18080` 配置与前端代理不一致的问题，避免重建后前端无法访问 API。

主要代码：`custom/services/general-agent/app/{working_context,workspace,runtime_tools,platform_runtime,sdk_runtime}.py`、`internal/custom/modules/conversationmemory/live_tools.go`，原生执行器仅接入上下文边界和恢复。配置整理脚本为 `custom/services/llmgateway-agent-policy/configure_eval.sql`，仅在本地 eval PostgreSQL 执行。

## 手动测试

打开 `http://localhost:5177`，先刷新一次页面。直接使用内置智能体，不创建对照配置；模型任选上述两个，需要切换时从输入框正常选择即可。

| 步骤 | 怎么操作 | 重点看什么 |
|---|---|---|
| 1. 选择与普通对话 | 确认模型列表仅两个，智能体列表为内置项。用“简单对话”发一个日常问题，再切换模型继续追问；打开一个以前用测试智能体的旧会话继续操作。 | 选择与实际请求一致，没有“模型/智能体不存在”，历史消息正常。 |
| 2. 制度多轮 | 用“智能推理”选择“公司制度”，按下方连续 13 轮提问。另用“快速问答”问一个自己熟悉的制度问题。 | 当前限定条件、跨轮指代、原文引用；切换话题后是否还沿用错误检索范围。 |
| 3. Wiki | 用“维基问答”选 `wikitest`，问有哪些主题，再指定其中一页追问依据；用“维基修订”在测试 Wiki 中检查一页及其引用，需要修改时由你明确提出。 | 页面读取与引用是否对应，检索或修订工具参数正确，修改结果是否有实际返回。 |
| 4. 通用与文档流程 | “文档处理”先提问“生成一个最简单的 PDF”，再要求改一个内容重新生成；“通用智能体”执行你之前的“整理茅台舆情并生成 PPT”。 | 是否真正调用必要工具，参数是否完整，是否反复重做同一步，是否有可打开的最终产物。重点看流程。 |
| 5. 数据与上传 | “数据分析”选择本地可用测试数据源，要求统计一张实际表，并按实际分类字段分组；“表格分析”上传你的数据资产 Excel，先问结构，再问一个实际统计问题。可补充上传 Word、PPT、图片后追问。 | 数据源/文件选择有没有丢失，工具是否读取正确对象，大结果是否可继续读取，后续提问能否利用前面结果。 |

每次回答后展开执行过程，查看**全部工具调用的名称、参数、结果及错误**；有引用就打开原文核对。不要按固定答案、固定工具调用次数或某个词出现与否来判定通过。遇到异常，保留会话链接、提问、所选模型及大致发生时间。

公司制度的 13 轮示例（在同一会话连续发送；涉及职责和条件应以实际原文为准，不预设答案）：

1. 在安全管理中发现隐患后，应当怎样报告和处理？请给出制度依据。
2. 我具体问数科事业部在这个环节的职责。
3. 这里的报告对象是谁，哪些情况下会不同？
4. 刚才的职责分别能在原文哪里找到？
5. 如果问题属于弱电系统，流程有什么区别？
6. 责任部门不能及时完成整改时，制度有没有规定后续措施？
7. 谁负责确认整改已经完成，依据是什么？
8. 把前面的发现、报告、整改、确认整理成流程，保留适用条件。
9. 换一个话题：报销单提交之后能不能修改？
10. 我说的是领导还没有审批的情况。
11. 如果已经审批了呢？请核对原文。
12. 回到前面的隐患问题：数科事业部是否对所有类型隐患都负同样责任？
13. 复核前面关于数科事业部的结论，区分原文明文、需要其他制度补充及证据不足的部分。

若自然遇到输出预算耗尽，观察能否继续利用已有结果、最后是否给出答案或明确失败。无需为了触发恢复而调小预算；人工构造的截断已经在协议测试中覆盖。
