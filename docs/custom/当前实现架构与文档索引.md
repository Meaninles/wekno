## 2. 服务入口与路由

生产入口：

| 能力 | 地址 |
|---|---|
| Web | `https://knora.moutai.com.cn/` |
| API | `https://knora.moutai.com.cn/api/v1` |
| 移动端 | `https://knora.moutai.com.cn/mobile/` |
| 嵌入页 | `https://knora.moutai.com.cn/embed/{channel_id}` |
| 对话分享 | `https://knora.moutai.com.cn/share/chat/{token}` |

核心 API 路由由 `internal/router/router.go` 注册，包括认证、租户、组织、模型、知识库、
知识条目、分块、FAQ、会话、消息、知识检索、Agent、Wiki、数据源、向量库、网络搜索、
MCP、嵌入、分享、IM、文件和系统管理。release 模式不挂载 Swagger UI；非 release 本地
调试环境才可使用 `http://localhost:8080/swagger/index.html`。

二开路由由 `internal/custom/bootstrap/bootstrap.go` 和 `internal/router/router.go` 注册，
当前包括 IAM、技能、定时会话、会话状态、聊天分享、数据库分析、Agent Runtime、回答反馈、
文件夹、移动端文档、Wiki 访问和运维控制等模块。

## 3. 文档处理链路

```text
上传/URL/文本
   │
   ├─ API 校验、租户/权限、对象存储写入
   ├─ parse 角色：读取与切片
   ├─ derivative 角色：摘要、问题、图谱等衍生任务
   ├─ Wiki 角色：Wiki 索引/地图任务
   └─ maintenance/恢复：租约、重试、清理和一致性维护
```

文档流程使用数据库事实、队列和租约共同推进。解析、衍生、Wiki、删除、移动和重建都
带有 generation/epoch/fencing 边界，迟到任务不能写回新的文档版本。删除不是只删一行，
还要清理 chunk、向量、问题、图谱、Wiki 引用和对象。任务完成必须依据业务状态，不以
容器退出或某次 HTTP 返回代替。

`internal/custom/modules/documentqueue`、`documentsplit`、`corefanout`、`derivativequeue`、
`wikiqueue`、`wikiingestguard`、`kbdeletequeue`、`retrievalfence` 和相关 recovery 模块
共同实现排队、派发、租约、超时、接管和清理。

## 4. 存储与隔离

| 数据 | 生产语义 | 本地验收语义 |
|---|---|---|
| 原始文件、图片、衍生对象、Agent 产物 | 受保护对象存储 | 本地对象存储服务 |
| 业务、工作流、chunk、向量 | PostgreSQL/ParadeDB | 本地 PostgreSQL |
| 实体和关系 | Neo4j | 本地 Neo4j |
| 队列、流、租约、准入 | Redis | 本地 Redis |
| 解析、Office、Agent 临时目录 | 按角色/Pod/任务隔离的本地 scratch | Compose 容器/命名卷隔离 |

生产不使用共享 RWX 作为运行工作区；Agent Runtime 使用预绑定静态 PVC 和每运行独立
subPath。对象存储不能替代 POSIX 临时目录。完整安全摘要见[无 RWX 部署方案](./生产集群无RWX最优部署方案.md)。

## 5. 统一 Agent Runtime

所有 Agent 问答使用 `agent_mode=agent` 和统一 Agent Runtime 入口。当前类型为：

`knowledge-qa`、`wiki-qa`、`hybrid-rag-wiki`、`data-analysis`、`table-analysis`、
`document-processing-agent`、`general-agent`、`knowledge-base-manager`、`custom`。

当前内置定义为：

`builtin-knowledge-qa`、`builtin-data-analyst`、`builtin-table-analyst`、
`builtin-general-agent`、`builtin-document-processing`、`builtin-wiki-fixer`（内部）。

预算由 `internal/types/custom_agent.go` 统一计算：知识问答 15；启用产物 100；其他普通
情况 50。`internal/custom/modules/agentruntime` 负责 Go 侧运行记录、工具注册、权限、
模型租约、事件和产物；`custom/services/agent-runtime` 负责 AgentScope 运行循环、文件
工作区和交付协议。Python 运行时不直接持有平台数据库、对象存储、MCP 或业务数据库凭据。

## 6. MCP、技能与反馈

- MCP 服务 CRUD、连通性测试、工具/资源发现、凭据子资源、OAuth、工具审批和对话内 OAuth
  解析由原生 MCP handler 和路由提供；主资源响应不返回 API Key/Token 明文。
- `custom/services/weknora-mcp-policy` 是独立可配置 MCP 适配层，当前白名单工具数为 32，
  写入工具不回显正文，下载工具受大小限制，返回内容递归脱敏。
- 技能分为轻量、预加载运行时和专业三类，分别由 skillhub、`skills/preloaded/` 和专业
  技能包处理，见[Agent 技能文档](../agent-skills.md)。
- 回答反馈使用 `solved`、`unsolved`、`off_topic`、`inaccurate`、`none`；分析接口位于
  `/api/v1/custom/answer-feedback/analytics*`。

## 7. 前端实现边界

`frontend/src` 当前包含桌面 Web、移动端、嵌入式、分享、IM 引用、技能、MCP、Wiki、文档
预览、队列、上传、产物和回答反馈。移动端入口由 `mobile-main.ts` 使用 `/mobile/` base；
嵌入入口为 `/embed/:channelId`。生产和本地入口的差异只在域名/端口，不改变移动端路径。

## 8. 角色化本地验收

本地后端固定使用 `custom/tests/runtime_profile_e2e/docker-compose.yml`，并先确保
`docker-compose.dev.yml` 的 PostgreSQL、Redis、MinIO、Neo4j 和基础 DocReader 已运行。
角色基线：

| 角色 | 本地数量 |
|---|---:|
| API | 3 |
| 解析 | 2 |
| 衍生任务 | 2 |
| Wiki | 2 |
| 维护 | 2 |
| 迁移 | 1 次性 |
| 运行时 DocReader | 2 + 入口；另有基础 DocReader |
| Agent Runtime/MCP | 以 Compose 当前定义为准 |
| API 入口 | 1，宿主机 `8080` |
| DocReader 入口 | 1 |

本地前端为 `http://localhost:5177`，移动端为 `http://localhost:5177/mobile/`，API 为
`http://localhost:8080`。不要使用单体 `app-dev` 作为本地后端启动方式，也不要使用 5178
作为移动端端口。
