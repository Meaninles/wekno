# 当前版本生产更新部署执行手册

> 本文只负责把当前仓库版本更新到现有生产 CCE，并让它稳定运行。  
> 本次不改造 PostgreSQL/Neo4j/Redis/LiteLLM，不建设跨 AZ、HPA、NetworkPolicy 或新的监控平台。

## 1. 本次上线后的固定形态

| 组件 | 副本 | 节点 |
|---|---:|---|
| app | 3 | `10.14.201.1/.2/.7` 各 1 |
| DocReader | 3 | `10.14.201.1/.2/.7` 各 1 |
| general-agent | 2 | `10.14.201.1/.2` 各 1 |
| document-processing-agent | 2 | `10.14.201.1/.2` 各 1 |
| frontend | 2 | `10.14.201.1/.2` 各 1 |
| mobile-web | 2 | `10.14.201.1/.2` 各 1 |

以下保持现状：

- PostgreSQL/ParadeDB：`.6` 单实例。
- Neo4j：`.54` 单实例。
- LiteLLM：`.6` 单实例。
- Redis：继续使用 `redis.weknora.svc.cluster.local:6379` 对应的现有外部 Redis。
- OBS：继续使用 `http://10.8.32.252` 和 bucket `ap-weknora-obs-zhengshi-01`。
- Ingress controller：继续使用 `.6/.54` 两个现有副本和域名 `knora.moutai.com.cn`。

本次不使用 RWX：

- 持久文件和 Agent 最终产物进入私有 OBS。
- app、DocReader、两个 Agent 使用各 Pod 独立的 `csi-local-topology` RWO 临时卷。
- `.1/.2` 新 500G 数据盘和迁移后的 `.7` 数据盘提供临时卷。

Anthropic/LiteLLM 运行参数由本手册从现网安全继承到
`weknora-model-runtime` Secret，不能依据旧文档手工重填或改用其他模型。

## 3. 上线前检查

```bash
export NS=weknora

kubectl get nodes -o wide
kubectl -n "$NS" get deploy,pod,svc,pvc,ingress -o wide
kubectl -n "$NS" get secret \
  weknora-secrets weknora-obs default-secret
kubectl get sc csi-local-topology -o yaml
command -v jq
command -v base64
```

必须确认：

- 5 个节点均为 Ready。
- `.1/.2` 的 500G 盘已经导入 Everest 本地卷池，不只是普通目录挂载。
- `csi-local-topology` 为 `WaitForFirstConsumer`。
- 现有 PostgreSQL、Neo4j、Redis、OBS、LiteLLM 都可用。
- `.1/.2/.7` 可以从 SWR 拉镜像。
- `.1/.2/.7` 的宿主 Docker 已认证 SWR或已经预拉取 sandbox 镜像。
- `.1/.2/.7` 都允许创建固定宿主目录 `/app/skills/preloaded`；目录内容将在
  6.2 节从本次 app 镜像逐节点导出，不能沿用来源不明的旧目录。

只做本次更新所需的最小备份：

```bash
mkdir -p /secure/weknora-update-backup

kubectl -n "$NS" get deploy,svc,ingress,pvc -o yaml \
  > /secure/weknora-update-backup/kubernetes-before.yaml
kubectl -n "$NS" get secret weknora-secrets -o yaml \
  > /secure/weknora-update-backup/weknora-secrets.yaml
kubectl -n "$NS" get secret weknora-obs -o yaml \
  > /secure/weknora-update-backup/weknora-obs.yaml
kubectl -n "$NS" get secret weknora-agent-internal -o yaml \
  --ignore-not-found \
  > /secure/weknora-update-backup/weknora-agent-internal.yaml
kubectl -n "$NS" get secret weknora-model-runtime -o yaml \
  --ignore-not-found \
  > /secure/weknora-update-backup/weknora-model-runtime.yaml
chmod 600 /secure/weknora-update-backup/*.yaml
```

同时完成当前 PostgreSQL、Neo4j 和 `/data/files` 的可恢复备份。这里不是新增备份平台，只是本次数据迁移的回滚点。

在删除或缩容旧 app 前，把它当前真正使用的模型和可选沙箱运行参数复制到专用
Secret。脚本支持旧 Deployment 直接写值或引用其他 Secret 两种形式；不会输出值，
也不会把 API key 放入进程命令行：

```bash
bash deploy/production/capture-model-runtime-secret.sh \
  "$NS" weknora-app app weknora-model-runtime
```

脚本必须成功。首次执行若缺少 `ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL` 或
`ANTHROPIC_API_KEY` 会直接失败；此时先核实现网真实配置，不能用占位值让部署继续。
目标 Secret 已存在时脚本只校验并保留，不会静默覆盖。不得把 Secret 解码到终端、
工单、Git 或部署文档。

## 6. 维护窗口和数据迁移

### 6.1 排空

在 ELB/WAF 或维护页切换为全站维护状态，暂时阻止 API、上传、重建、删除和
Agent 新任务。等待现有文档和 Agent 任务结束；确认不存在
`pending/processing/finalizing` 文档或 Agent 运行后，备份并移除业务 Ingress，
再停掉全部无状态业务 Pod：

```bash
kubectl -n weknora get ingress weknora -o yaml \
  > /secure/weknora-update-backup/ingress-before.yaml
kubectl -n weknora delete ingress weknora

for deployment in \
  weknora-app \
  weknora-docreader \
  weknora-custom-general-agent \
  weknora-custom-document-processing-agent \
  weknora-general-agent \
  weknora-document-processing-agent \
  weknora-frontend \
  weknora-mobile-web
do
  kubectl -n weknora scale deploy "$deployment" \
    --replicas=0 --timeout=2m 2>/dev/null || true
done

kubectl -n weknora get pod -o wide
```

确认所有上述 Pod 均已退出。不要在仍有文档
`pending/processing/finalizing`、Agent 运行或外部 API 仍可访问时切换存储。

目标 app 和两个 Agent 必须共享一个内部 API key。如果 Secret 尚不存在，只在所有旧
app/Agent Pod 都已退出后创建；如果已经存在则保留原值：

```bash
if ! kubectl -n weknora get secret weknora-agent-internal >/dev/null 2>&1; then
  AGENT_API_KEY="$(openssl rand -hex 32)"
  kubectl -n weknora create secret generic weknora-agent-internal \
    --from-literal=apiKey="$AGENT_API_KEY"
  unset AGENT_API_KEY
fi

kubectl -n weknora get secret weknora-agent-internal \
  -o jsonpath='{.data.apiKey}' | base64 -d | wc -c
```

最后一条必须输出大于等于 32；不要把实际 key 打进终端日志或部署文档。

### 6.2 为三个 app 节点预置同版本沙箱技能

app Pod 通过宿主 `/var/run/docker.sock` 启动 sandbox。sandbox 的 `-v` 参数由宿主
Docker 解析，因此技能脚本不仅要存在于 app 镜像，还必须以同一个绝对路径存在于
`.1/.2/.7` 的宿主机。否则 app 可以列出技能，但 sandbox 真正执行时会挂载空目录或
直接失败。

以下命令在 `.1/.2/.7` 三个节点上分别以 root 权限执行。三个节点必须使用同一个
`GIT_SHA`，并且先确认当前节点没有旧 app Pod：

```bash
set -euo pipefail

export GIT_SHA="<the-same-12-char-release-sha>"
export SWR="swr.cloud-mt-1.moutai.com.cn/<actual-namespace>"
export APP_IMAGE="$SWR/weknora-app:$GIT_SHA"
export SANDBOX_IMAGE="$SWR/weknora-sandbox:$GIT_SHA"
export SKILL_LIVE="/app/skills/preloaded"
export SKILL_STAGE="/app/skills/preloaded.new-$GIT_SHA"
export SKILL_BACKUP="/app/skills/preloaded.backup-$(date +%Y%m%d%H%M%S)"

docker pull "$APP_IMAGE"
docker pull "$SANDBOX_IMAGE"
docker image inspect "$APP_IMAGE" --format '{{.Id}} {{index .RepoDigests 0}}'
docker image inspect "$SANDBOX_IMAGE" --format '{{.Id}} {{index .RepoDigests 0}}'

test ! -e "$SKILL_STAGE"
install -d -m 0755 "$SKILL_STAGE"
export SKILL_EXPORT_CONTAINER="$(docker create "$APP_IMAGE")"
trap 'docker rm -f "$SKILL_EXPORT_CONTAINER" >/dev/null 2>&1 || true' EXIT
docker cp \
  "$SKILL_EXPORT_CONTAINER:/app/skills/preloaded/." \
  "$SKILL_STAGE/"
docker rm "$SKILL_EXPORT_CONTAINER"
trap - EXIT

for skill in \
  citation-generator \
  data-processor \
  doc-coauthoring \
  document-analyzer
do
  test -s "$SKILL_STAGE/$skill/SKILL.md"
done
test -s "$SKILL_STAGE/data-processor/scripts/analyze.py"
test ! -L "$SKILL_LIVE"

chown -R 1000:1000 "$SKILL_STAGE"
chmod -R a-w "$SKILL_STAGE"
find "$SKILL_STAGE" -type d -exec chmod a+rx {} +
find "$SKILL_STAGE" -type f -exec chmod a+r {} +

if [ -e "$SKILL_LIVE" ]; then
  mv "$SKILL_LIVE" "$SKILL_BACKUP"
fi
if ! mv "$SKILL_STAGE" "$SKILL_LIVE"; then
  if [ -e "$SKILL_BACKUP" ]; then
    mv "$SKILL_BACKUP" "$SKILL_LIVE"
  fi
  exit 1
fi

find "$SKILL_LIVE" -mindepth 1 -maxdepth 2 \
  -type f -name SKILL.md -print | sort
```

保留 `preloaded.backup-*` 直到上线验收完成，不在本次过程中直接删除。记录三个节点
输出的 app/sandbox image ID 和 RepoDigest；三个节点必须完全一致。这里不能把
sandbox 改成进程模式，也不能删掉技能来规避宿主目录问题。

### 6.3 单实例执行数据库迁移和旧 Agent 产物迁移

```bash

sed -i 's/REPLACE_LEGACY_NODE_NAME/<actual-node-name-for-.7>/' \
  /secure/values-migration.yaml
```

迁移实例：

- 只有一个 app。
- 固定在 `.7`。
- 挂旧 `weknora-data-files` PVC。
- `AUTO_MIGRATE=true`。
- 不接收用户请求。

渲染：

```bash

  -f helm/values-production-ha.yaml \
  -f /secure/values-site.yaml \
  -f /secure/values-migration.yaml

helm template weknora ./helm -n weknora \
  -f helm/values-production-ha.yaml \
  -f /secure/values-site.yaml \
  -f /secure/values-migration.yaml \
  --show-only templates/app.yaml \
  > /secure/weknora-migration-app.yaml
```

备份并替换旧 app Deployment：

```bash
kubectl -n weknora get deploy weknora-app -o yaml \
  > /secure/weknora-update-backup/app-before.yaml
kubectl -n weknora delete deploy weknora-app
kubectl apply --dry-run=server -f /secure/weknora-migration-app.yaml
kubectl apply -f /secure/weknora-migration-app.yaml
kubectl -n weknora rollout status deploy/weknora-app --timeout=30m
```

检查日志，必须看到数据库 migration 成功，且旧 Agent 产物全部迁入 OBS。数据库检查：

- 维护实例必须执行 native/custom migrations，以及既有用户的使用指南和内置智能体默认项回填。
- 后续正常 3 个 app 必须输出
  `schema/data migrations and existing-user backfills disabled; maintenance replica must have completed them`；
  这证明没有在多副本启动时并发执行 DDL，也没有跨 Pod 重复创建使用指南资源。

```sql
SELECT storage_state, count(*)
FROM custom_general_agent_artifacts
WHERE deleted_at IS NULL
GROUP BY storage_state;

SELECT count(*)
FROM custom_general_agent_artifacts
WHERE deleted_at IS NULL
  AND file_path !~ '^(obs|minio)://';
```

有效记录必须全部 `ready`，第二条必须为 0。

停止迁移 app 并等待至少 45 秒：

```bash
kubectl -n weknora scale deploy/weknora-app --replicas=0
```

### 6.5 释放 `.7` 数据盘

对旧 `/data/files` 做一份离线归档和 SHA256 清单。确认：

- 历史 Agent 产物可从 OBS 下载。
- storage audit 为 0。
- 数据库不再引用本地路径。

然后删除经现场确认的旧 PVC/PV：

```bash
kubectl -n weknora get pvc weknora-data-files -o yaml
kubectl -n weknora delete pvc weknora-data-files
```

从 PVC 的 `spec.volumeName` 取得实际 PV 名，确认无误后再删除对应 PV。随后把 `.7`
数据盘加入 Everest 本地卷池。目标工作负载在 `.1/.2` 各申请 240Gi、在 `.7`
申请 180Gi 临时卷；上线前本地卷池的实际可分配空间必须分别不低于 300Gi、220Gi，
不能只看云盘标称容量或节点文件系统剩余空间。

在 `.1/.2/.7` 逐节点执行下面的真实动态 PVC 写、读、删除回收测试。`APP_IMAGE`
沿用 6.2 节的本次不可变镜像，`LOCAL_PV_NODE` 每次替换为一个真实 Kubernetes node
name：

```bash
export LOCAL_PV_NODE="<one-real-node-name>"
export LOCAL_PV_TEST_ID="$(date +%s)"
export LOCAL_PV_PVC="wk-local-pv-$LOCAL_PV_TEST_ID"
export LOCAL_PV_JOB="wk-local-pv-$LOCAL_PV_TEST_ID"

cat <<EOF | kubectl -n weknora apply -f -
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: ${LOCAL_PV_PVC}
  labels:
    weknora.io/local-pv-smoke: "${LOCAL_PV_TEST_ID}"
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: csi-local-topology
  resources:
    requests:
      storage: 1Gi
---
apiVersion: batch/v1
kind: Job
metadata:
  name: ${LOCAL_PV_JOB}
  labels:
    weknora.io/local-pv-smoke: "${LOCAL_PV_TEST_ID}"
spec:
  backoffLimit: 0
  template:
    metadata:
      labels:
        weknora.io/local-pv-smoke: "${LOCAL_PV_TEST_ID}"
    spec:
      restartPolicy: Never
      nodeSelector:
        kubernetes.io/hostname: "${LOCAL_PV_NODE}"
      imagePullSecrets:
        - name: default-secret
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        runAsGroup: 1000
        fsGroup: 1000
        fsGroupChangePolicy: OnRootMismatch
      containers:
        - name: verify
          image: ${APP_IMAGE}
          imagePullPolicy: IfNotPresent
          command:
            - /bin/sh
            - -lc
          args:
            - >-
              printf 'local-pv-ok\n' > /scratch/probe &&
              sync &&
              test "\$(cat /scratch/probe)" = local-pv-ok &&
              cat /scratch/probe
          volumeMounts:
            - name: scratch
              mountPath: /scratch
      volumes:
        - name: scratch
          persistentVolumeClaim:
            claimName: ${LOCAL_PV_PVC}
EOF

kubectl -n weknora wait --for=condition=complete \
  "job/$LOCAL_PV_JOB" --timeout=5m
kubectl -n weknora logs "job/$LOCAL_PV_JOB"
kubectl -n weknora get pod \
  -l "weknora.io/local-pv-smoke=$LOCAL_PV_TEST_ID" -o wide
export LOCAL_PV_NAME="$(kubectl -n weknora get pvc "$LOCAL_PV_PVC" \
  -o jsonpath='{.spec.volumeName}')"
test -n "$LOCAL_PV_NAME"
kubectl get pv "$LOCAL_PV_NAME" -o yaml

kubectl -n weknora delete job "$LOCAL_PV_JOB" --wait=true
kubectl -n weknora delete pvc "$LOCAL_PV_PVC" --wait=true
kubectl wait --for=delete "pv/$LOCAL_PV_NAME" --timeout=5m
```

每次日志必须只有 `local-pv-ok`，Pod 的 `NODE` 必须是指定节点，PV 的 node affinity
也必须指向该节点，并且删除 PVC 后 PV 能正常回收。三次任一失败都不得继续部署。

## 7. 部署最终多副本

渲染：

```bash
helm lint ./helm \
  -f helm/values-production-ha.yaml \
  -f /secure/values-site.yaml

helm template weknora ./helm -n weknora \
  -f helm/values-production-ha.yaml \
  -f /secure/values-site.yaml \
  > /secure/weknora-production.yaml

grep -n "REPLACE_\\|horizontal-objectstore-20260726" \
  /secure/weknora-production.yaml
kubectl apply --dry-run=client -f /secure/weknora-production.yaml
kubectl diff -f /secure/weknora-production.yaml
```

grep 必须没有输出。`kubectl diff` 可能因旧 Deployment selector 或 DocReader
Service 的 `clusterIP` 不可变而报告冲突；只能接受下文明确删除重建的资源出现这两类
差异，其他错误必须先处理。现网资源不是活动 Helm release，本次不要运行
`helm upgrade --install`，也不要使用 `kubectl apply --prune`。

删除并重建的只有无状态业务 Deployment。列表同时包含现网旧 Agent 名称和目标清单
名称，确保重复执行时不会残留两套 Agent：

```bash
for deployment in \
  weknora-app \
  weknora-docreader \
  weknora-custom-general-agent \
  weknora-custom-document-processing-agent \
  weknora-general-agent \
  weknora-document-processing-agent \
  weknora-frontend \
  weknora-mobile-web
do
  kubectl -n weknora delete deploy "$deployment" --ignore-not-found

```

## 8. 必须通过的上线检查

### 8.1 单实例能力等价门槛

本次只能改变实例数量、工作流分配、故障接管和长期文件落点，不能减少原单实例的
功能。以下任何一项不通过，都按上线失败处理，不能用关闭开关、换轻量模型、减少
格式或跳过衍生任务来换取通过：

| 能力 | 必须保持的生产行为 | 验收证据 |
|---|---|---|
| 身份与权限 | 原 PostgreSQL、`JWT_SECRET`、AES key 和 IAM SSO 设置原样复用；桌面端和移动端都可登录 | SSO 真登录、已有用户/租户/权限实查 |
| 对话模型 | 继承旧 app 的 LiteLLM 地址、模型名和认证，不替换 DeepSeek V4 Flash | 三个 app 均具备必需环境变量，API 实际完成一次对话 |
| 召回 | 原知识库 embedding、rerank、检索配置不改 | 用已知文档问题核对召回 chunk、分数和答案引用 |
| 文档解析 | 原支持格式全部保留；单 DocReader 仍为 4 worker、PDF render parallelism 4 | PDF/Word/Excel/PPT/图片/音频逐类完成 |
| 多模态与音频 | 不关闭知识库的 VLM/ASR，继续使用原配置的 Qwen VLM 和当前生产 ASR | 图片理解结果、音频转写文本及后续向量实查 |
| 衍生任务 | 摘要、问题生成、知识图谱、Wiki 开关和结果完整性不变 | PostgreSQL 状态/行、Neo4j 节点关系、Wiki 页面三方核对 |
| 智能体 | 通用智能体和文档处理智能体的全部原能力保留，产物仍可生成、下载、删除 | 两类 Agent 各自特色用例及私有 OBS 产物实查 |
| 沙箱技能 | 仍为 Docker 模式，原预载技能、模型环境和现网网络策略均继承 | 每个 app 节点运行 sandbox；原 4 个技能逐个 smoke |
| Web | 桌面和移动端都保留；状态、筛选、排队、预览和图谱渐进展示正确 | 浏览器 E2E 与后端/数据库状态逐项比对 |
| 生命周期 | 上传、重建、解析中删除、完成后删除、重启续跑均不丢失或重复 | API、队列状态、数据库、OBS、Neo4j 联合检查 |

`AUTO_RECOVER_DIRTY=false` 不是关闭故障恢复：新版使用 PostgreSQL 持久化的文档级
租约、心跳、boot fencing 和 Kubernetes 终止证明接管任务；旧 dirty recovery 与
新状态机同时运行反而可能重复领取，因此必须关闭旧路径。类似地，单 app 文档并发
从旧值 8 改为每实例 4 后，正常总容量为 12；即使一个 app 故障仍剩 8，与旧单实例
容量相同，且每份文档仍执行完整衍生链路。模型准入只允许等待/重试或明确失败，
不得把被限流的任务标成完成或跳过。

    'test -n "$ANTHROPIC_BASE_URL" &&
     test -n "$ANTHROPIC_MODEL" &&
     test -n "$ANTHROPIC_API_KEY"'

### 8.4 多实例和故障

- 日志/处理 span 必须证明 3 个 app、3 个 DocReader、两个 Agent 都收到真实任务。
- 删除一个空闲 app Pod，确认其他 app 正常。
- 在专用测试文档处理中删除一个 app Pod，确认任务恢复且没有重复结果。
- 删除一个 DocReader Pod，确认解析自动转到剩余 endpoint。
- 删除一个 Agent Pod，确认其他副本仍可运行新请求。
- 测试解析中删除文档，确认任务取消且衍生数据清理。
- 同时从多个 app 触发 IAM 同步，`custom_iam_sync_runs` 只能新增一个
  `running` 记录，其他请求返回同一 run；不得向 IAM 重复发起同步。

不要用“公司制度”知识库做破坏性故障测试，也不要在它正常时重新解析。

## 9. 开放流量

只有以下全部成立才解除维护：

- 所有目标副本 Ready 且分布正确。
- 后端知识源原文件上限仍为 2048MiB，Ingress、ELB、WAF 和桌面/移动 Nginx 的
  request-body 上限统一为至少 2304MiB，给 multipart 边界和请求元数据留出余量；
  入口放宽不改变后端原文件校验。request buffering 关闭，外层和桌面/移动 Nginx
  的 read/send timeout 都是 7200 秒。
- 普通聊天/Agent 原附件仍限制为 50MiB；桌面/移动 Nginx 入口为 80MiB。若在
  app→Agent 的内部路径增加 Nginx、Service Mesh sidecar 或 API gateway，其
  request-body 至少为 128MiB，以覆盖约 66.7MiB 的 Base64 数据及 JSON 元数据。
- API、桌面端、移动端通过。
- 向量、摘要、问题、图谱、Wiki 全部实查完成。
- app/DocReader/Agent 多实例实际执行得到证明。
- 单 Pod 故障恢复通过。
- PostgreSQL、Redis、OBS、Neo4j、LiteLLM 无连接异常。
- 节点没有 OOM、DiskPressure 或 PVC 创建失败。

开放后先观察小流量，再恢复正常批量上传。当前系统管理员并发保持每 app 4，集群完整文档并发为 12，不要在上线当天继续调大。
