## 本阶段新增的确定根因与对照

### 内置智能推理仍加载旧提示正文

本地内置智能推理的持久配置保存了 11,612 字符正文、模板 ID 为空。配置解析优先使用正文，因此仓库模板已简化也不会应用到此智能体。其他内置智能体使用模板 ID，更新路径不同；编辑器还会把模板正文重新写入配置。

修复统一在配置边界解析、校验和保存模板引用：与当前模板逐字相同的正文归一化为模板 ID，用户编辑过的正文保留。内置智能推理明确绑定其预设模板。内置更新和前端选择也走相同约定。

只改变这个本地内置配置、保持模型/采样/问题/索引不变的 8 次实际回答已人工读完；部分任务模型往返减少，但制度责任主体、将未提及解释为无要求、跨单据推广等错误仍存在，**不能宣布单独简化提示解决准确性问题**。

### 编号父段落缺失造成证据对象不完整

制度中的子条目跨块时，来源保留了章、条，却未保留“（二）……”等编号父段落。实际检索片段从第 2/3 子项开始，缺少“公司分管安全领导”这一父段落，回答误归给“公司主要负责人”。

修复按通用编号层次保存原文字面祖先，使用项目审核/执行方等独立样例验证边界和同级切换。真实制度需在新版重新处理后再检查；此缺陷不能解释模型已拿到完整条件却仍推断错误的全部情况。

### 嵌入页附件创建时混用了临时身份和真实账户

实际嵌入页上传正常文本和损坏 PDF，两者均在创建私有知识库时收到 `value too long for type character varying(36)`，尚未进入解析。认证使用 `embed-` 加渠道 UUID 作为临时身份；创建知识库却把这个 42 字符字符串写入真实账户创建者字段。

修复共用账户身份解析：只有真实 Web 账户作为自己操作时才写入创建者；访客会话依旧由完整会话身份控制附件访问。知识库及智能体的创建/复制使用同一边界。身份与服务测试通过，实际嵌入页回归将在版本 12 上执行。

### 大文件分片完成后仍反复扫描向量表

约 127.17 MiB 的 Excel 已完成 50/50 分片，发布阶段每批启用 100 个片段。数据库 `embeddings.chunk_id` 缺少 B-tree，BM25 索引不能替代普通等值更新索引；执行计划确认每批扫描整张表。

对同一批 100 个已启用测试片段，查询使用 `EXPLAIN ANALYZE`，更新使用事务内 `EXPLAIN ANALYZE` 后回滚；前后各执行两次：

| 操作 | 加索引前 | 加索引后 |
|---|---|---|
| 定位 100 个片段 | 130.114 / 202.166 ms | 1.318 / 1.538 ms |
| 更新并回滚 | 848.611 / 650.940 ms | 370.565 / 330.963 ms |

共享发布迁移补上片段身份索引。状态批量更新只写入实际改变的行，避免任务恢复时重写已启用向量。真实 PostgreSQL 隔离测试验证重试保留状态与时间戳、发布期间仍召回正确版本。

上述数字是数据库阶段对照，不能外推为整个文件处理提速。大 Excel 的逐行向量化和索引维护仍有显著成本，尚未完成最终 Ready 后的实际使用验收。
