# 智能体结构修复与人工回归

日期：2026-09-05。工作树：`C:\weknora-agent-eval-loop`。仅使用本地 `37430534@qq.com` 的环境、知识库和 Docker Desktop 测试数据源，没有访问生产数据。

## 验收口径

本轮依据《智能体根因验证与结构精简方案-2026-09-05.md》实施共享链路修复。没有为具体问题改写提示词、植入答案、增加关键词分支或要求回答匹配参考措辞。自动化只采集问答、流事件、工具原始参数/返回、数据库真值、文件字节及时间。语义验收由人工阅读完成；最终答对但工具出错、引用不支持、追加无依据结论，均单独记录。

本报告不提供“关键词命中率”或单一“全部通过”标签，也不把因交付失败而没有输出错误答案计为精度提升。模型不遵循要求、系统执行错误、资料自身冲突和检索遗漏需要分别判断。

## 文档新增失败的确切链路

两页“季度培训安排”PPTX+PDF 任务，253.905 秒后失败，没有交付文件。SSE 保存了完整工具过程：

1. 约 64 秒生成 PPTX，python-pptx 成功重新打开，2 页。
2. LibreOffice 多次返回 `source file could not be loaded`。同目录生成最小 PPT 也失败；同样方式转换 TXT、DOCX 成功。镜像安装了 Writer、Calc、Draw，**缺少 Impress**。
3. 模型转而写另一套 PDF 生成脚本，又遇到字体路径和 PyMuPDF API 使用错误；累计 39 轮、约 140.9 万输入 token。真实文件工具多为几十到几百毫秒，时间主要消耗在连续模型往返。
4. 最后原生 `Read` 读取 PNG，将 image 内容块交给仅支持文本工具结果的 DeepSeek-V4-Flash，网关返回 HTTP 400。**“Claude SDK”是运行框架，不代表本次调用的是 Claude 模型。**
5. 错误路径仅有实时进度，持久消息没有 agent_steps，导致刷新后看不到已经执行的工具。测试最初只读持久工具列表也会误判成“没有调用工具”。

据此补齐两种 SDK 镜像的 Impress；使用已有平台 VLM 服务提供通用 `inspect_image`，本地文件适配成图像输入，主模型收到文本观察；按主模型真实能力限制原生多模态 Read，保留视觉检查能力。图像审查结果不等同于批准，仍由主模型决定如何修改。新增 transport 的输入 hash 可追溯，base64 不写入对话历史。失败/取消运行将已有执行步骤交给公共消息收尾逻辑保留。

上述改动针对格式组件和模型能力合同，未针对本题字体、标题、月份或排版写任何规则。新版本仍需以实际生成文件及视觉检查验收。

v4 实测已完成：148.629 秒交付 PPTX（30,941 字节）和 PDF（65,507 字节），API 实际下载 hash 均与持久记录一致。PPTX 可重新打开，PDF 两页文字提取完整；人工打开两张渲染图确认月份/课程、研发 12/财务 8/运营 10/合计 30，未见遮挡或裁切。实际工具调用包括两次 `inspect_image`，均使用配置中的 `prod-qwen3-vl-32b-vlm`；主模型没有收到 image 内容块。视觉模型将第二页左对齐标题误描述为“居中且带下划线”，因此其评价不是人工验收的替代品。

Word v2 两个下载文件逐个 ZIP 部件比较，只有 `word/document.xml` 改变，替换目标日期后该部件也逐字节一致；第二版已渲染人工查看，标题、林舟、待确认及日期 10月16日显示正常。

回归中曾尝试要求 SDK 正文必须包含完整私有边界，实际导致正常回答被拦截，已撤回该加严要求：当前以 SDK 成功的 `end_turn` 结果作为正常交付依据，存在边界时只投影其正文，不增加修复模型回合。该失败实验保留，不能计为精度改善；模型把内部分析写入普通文本通道的问题仍需单独观察，不能用“不给用户答案”掩盖。

## 公司制度连续 15 轮

按用户要求，快速问答、智能推理、通用各连续 15 轮，共 45 轮。问题序列固定为：青海三天→江苏四天→负责人→更正普通员工→住宿无发票假设→会议食宿假设→合同审查→采购合同→新员工安全培训→一般培训对比→回顾差旅事实→最终青海两天→退改签追问→无发票条件追问→完整办理说明。

重点检查：指代是否正确；旧条件是否失效；假设是否被错误当成事实；不同制度是否串用；隔多轮后是否从用户原文恢复；是否重新获取当前引用；是否遗漏批准和实际发生前提。
