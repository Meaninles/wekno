## 已落实的修改

1. 网关新增 DS 0731 和 Qwen3.8 专用 Agent 模型名，以官方采样配置统一处理 OpenAI 和 Anthropic 协议。旧模型名保留原采样行为，避免生产 WeKnora 被强制切换。模型权重和上游地址不变。
2. 修复 LiteLLM 将公开模型名替换为内部模型名后丢失参数策略身份的问题。Qwen 的原生 `xhigh` 不再误走旧枚举校验；通过请求上下文保留身份，退出时清理。
3. 本地 Go 原生协议和 AgentScope Harness 都传递模型级思考强度，关闭思考时不发送强度。Go 不再因 JSON omitempty 丢掉显式 temperature=0；原生 Anthropic 开启思考时省略不兼容的采样字段。网关专用模型的采样以网关策略为准。
4. 前端可编辑思考强度，并按实际选用的模型显示温度是否由网关管理、是否支持 SDK 温度设置。
5. Anthropic 空终止不再是成功：非流返回错误，流返回标准 Anthropic 错误事件。仅在 Python/网关内部抛异常会被 LiteLLM 转成 OpenAI 错误格式，AgentScope Harness 可能将断流当作成功空结果；完整 HTTP 测试和客户端测试已覆盖此问题。
6. 本地平台循环对未产生任何答案/工具的空 stop 仅以完全相同的输入重试一次，计入原调用次数上限；不回放已执行工具、不修改提示词、不执行思考中的 XML。该措施只处理失败交付，不是 Qwen 解析根因的修复。
7. SDK 失败时保留明确的 API 状态和错误内容，减少仅展示不完整结果的笼统错误。

采样依据：[DS 0731 官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731)、[Qwen3.8 官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)。不将“官方默认强度”解释为所有任务都更快或更准确。

## Qwen PPT 场景：尚未通过完整业务验收

生产长任务的原始 SDK 文件此前已被清理，只保留调用计数和空结果等记录。因此不能把历史长循环的每一步原因断言为同一根因。

本地同问题出现两类明确失败：

- 会话 <ID>，22.420 秒：上游最终返回 stop，仅有 312 字符 reasoning_content，其中是完整工具 XML；没有正文和结构化 tool_calls。
- 会话 <ID>，223.243 秒：生成 PPT 脚本的工具 XML 再次全部处于思考字段，最终 finish_reason=length，completion_tokens=8192。此结果不是前端漏显示，也不能视为成功。
- SDK 会话 <ID>，51.724 秒：触发网关空终止校验，但流式异常格式使 SDK 报 success、空 result。由此补充了标准 Anthropic SSE 错误处理；模拟完整 HTTP 链路和 Anthropic 客户端均验证了修复。

### 已证实的上游解析问题

直接读取受保护模型服务的 `/get_server_info`：版本、模型路径和解析器配置均已核对，但不写入版本化文档。

使用同一份失败记录的原始流式分块，在未改动的官方解析器类上进行对照：

| 解析器来源 | 思考字符 | 交给正文/工具层的字符 |
|---|---:|---:|
| SGLang v0.5.10 Qwen3Detector | 312 | 0 |
| SGLang 官方 Qwen3.8 推荐提交 1cf2b8c 的 Qwen3Detector | 0 | 312 |

新版显式将 `<tool_call>` 作为思考结束边界，源码说明 Qwen 可能不输出 `</think>` 就开始工具调用。旧版缺少此行为，正好复现真实失败的字段归类。参见 [官方新解析器](https://github.com/sgl-project/sglang/blob/1cf2b8c54d81802abc15dcf23a29b9cc687bc01e/python/sglang/srt/parser/reasoning_parser.py#L328) 与 [Qwen3.8 官方 SGLang 部署说明](https://docs.sglang.io/cookbook/autoregressive/Qwen/Qwen3.8-27B)。该实验验证字段解析根因，不等于已验证整份 PPT 的内容和排版。

后续应在 Qwen 模型服务部署包含官方修复的解析器版本，保留相同权重、采样、8192 输出限制和问题输入，对照原始失败流、完整多轮工具调用、正常思考和关闭思考，再验证交付 PPT。模型服务 `<MODEL_SERVICE_ENDPOINT>` 在当前“只改网关和本地 WeKnora”的范围之外，尚未修改。未在 WeKnora 或网关增加从思考 XML 猜测工具调用的业务补丁。

## 用户后续决定：Qwen 关闭思考，DS 保留（v4）

用户撤销了升级 Qwen 上游解析器的方向，要求 Qwen 关闭思考、DS 保留。v4 在已有网关参数策略中将 `Qwen3.8-27B-Agent` 配置为统一非思考路由，不依赖各智能体单独设置，避免用户切换模型后复用的 thinking=true 再次开启 Qwen 思考。DS 与旧生产模型别名不变；未修改模型服务或生产 WeKnora。

参数测试 6 项、LiteLLM 实际运行时测试 4 项、完整代理及 Anthropic SDK 错误识别测试通过。真实 16 项接口请求完成；Qwen Agent 的思考字段为空，DS 开启思考时仍返回思考内容。真实两轮工具回归 8 组均执行 lookup_record 并得到终答，但 Qwen 的工具后终答仍出现字面 `</think>` 和重复表述，不能宣称回答质量完全通过。未用字符串过滤掩盖该上游输出问题。
