# 模型思考与正文协议边界修复

日期：2026-09-07。开发工作树：`C:\weknora-agent-eval-loop`。

## 根因与证据

图片问答的最终正文出现“完整回答、`</think>`、完整回答”。定位到模型 HTTP 原始流已经如此：两份内容都在 OpenAI Chat 的 `delta.content` 中，没有独立的 reasoning 字段。视觉识别工具与检索证据本身干净；SDK 把 content 组装为一个 TextBlock，统一运行内核随后原样生成正文事件、检查点和最终答案。因此仅修改前端显示或对最终答案去重无法修复上下文污染。

原始失败运行：`1a365409-8805-4a46-a9aa-317c308b4b92`。随后在完整运行环境复现，保存原始响应用于离线重放；简化请求未复现，说明并非所有请求都会触发。证据位于本地忽略目录 `.local-data/agent-runtime-validation/provider-reasoning-leak.sse`，临时抓取代码已随容器重建移除，没有增加常驻响应记录。

这一接口使用 content 内联思考标记，可能只返回关闭标记（聊天模板可预填开启标记），而原适配只处理原生独立思考字段。应用与提供方之间缺少明确的输出格式约定。

## 通用修改

- 模型配置增加 `parameters.extra_config.reasoning_format`：默认 `native`；已确认使用内联标记的 OpenAI Chat 服务配置为 `think-tags`。Go 校验并传入运行内核，当前开发环境的 Qwen3.6-27B 已配置。新增此类模型也应显式声明该字段，不依靠模型名称猜测。
- 在统一模型适配层、SDK 累积消息之前，将内联思考和最终正文转换为 SDK 的 ThinkingBlock 和 TextBlock。流式事件、检查点、后续上下文及最终交付共用这一结果。所有使用该模型的智能体均生效。
- 处理开启标记缺省、跨分片标记、CRLF 和结束包边界。工具参数不参与文本解析；保留引用标记、用量和原生思考字段。关闭流时释放底层提供方迭代器。
- 普通重复文字不会按语义去重。原生协议的字面标记保持原样；内联协议保留代码块、引用及行内代码中的字面标记。显式开启但未结束的思考不能当成答案提交，走已有不完整响应错误流程。
- 不增加模型调用、答案纠正、前端遮盖、问题匹配或对话 ID 分支。既有历史消息不作回写。

## 性能与边界

内联协议省略开启标记时，首段究竟是草稿还是答案存在歧义，必须等关闭标记或响应结束才能确定。标记出现后正文正常流式输出；没有标记的普通回答在响应结束时释放。这可能延后首字展示，但不增加生成次数。原生独立思考字段协议保持原流式行为；若提供方以后规范输出独立字段，应将模型配置改为 `native`。

本次解决思考与正文协议混淆，不代表模型的引用选择已完全稳定：第一轮纯改写未带引用，第二轮带引用，已如实记录，未通过额外生成或伪造引用处理。两轮结果也不能证明所有未来回答均无错误。
