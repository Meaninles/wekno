# WeKnora 系统使用说明

> 当前实现交付版，更新日期：2026-08-12。
> 本文说明用户和管理员如何使用当前系统，特别是文档完整状态、排队、文件夹、
> 大文件预览、Wiki 图和文档生命周期。更完整的功能指南见
> [用户使用指南](./使用指南/用户使用指南.md)。
> 当前生产模型、容量与部署边界见
> [当前生产实现与部署基线](./当前生产实现与部署基线.md)。

用户界面当前品牌为“茅台智汇”；API、嵌入 SDK 和技术配置仍使用 WeKnora 名称。

## 1. 登录与工作区

- 桌面 Web 使用账号密码或企业 SSO。
- 移动端登录态失效时进入企业 SSO，不保留错误的本地登录文案。
- 登录后先确认当前租户/工作区。
- 共享空间中的资源仍保留原始归属和权限。

角色：

| 角色 | 权限概要 |
|---|---|
| viewer | 查看、检索、对话 |
| contributor | 按授权创建和编辑 |
| admin | 管理租户资源和成员 |
| owner | 租户最高权限和高风险操作 |
| system admin | 平台级模型、解析器、实例和默认配置 |

## 2. 创建知识库

创建文档知识库时依次确认：

1. 名称、说明和访问范围。
2. 向量、关键词、Wiki、实体图谱等索引策略。
3. Chat/摘要模型、Embedding、Rerank。
4. 图片使用 Qwen3-VL-32B；音频使用 Qwen2.5-Omni-7B。旧 Qwen ASR 1.7B 已下架，
   不应出现在知识库或智能体选择项中。
5. 解析器和分块策略。
6. 问题生成和实体/关系抽取。
7. 存储和外部数据源。

启用的能力会进入文档完整完成契约。不要启用后又把失败解释成“已跳过”。

## 3. 上传和导入

知识库支持：

- 上传单个或多个文件。
- 上传本地文件夹。
- URL 导入。
- 手工 Markdown。
- 外部内容源同步。

上传确认窗口可为本批次覆盖：

- 解析器。
- 分块。
- 多模态/VLM。
- ASR。
- 问题生成。
- 知识图谱。

这些覆盖只作用于本批文档，不修改知识库全局默认。

### 3.1 文件夹

- 在知识库内创建、重命名、移动和删除管理型文件夹。
- 文件、URL 和手工内容可直接创建到指定文件夹。
- 文件夹上传会安全解析相对路径并创建中间目录。
- 移动文档只改变管理位置，不复制向量或重建文档。
- 目录、文档和搜索均服务端分页/渐进加载。

## 4. 文档排队

当前外层队列单位是一份完整文档，不是解析、向量、Wiki、图谱等任务类型。

文档卡片会显示：

- 系统当前等待文档总数。
- 当前文档在全系统的等待位置。
- 简洁的完整工作流状态。

位置按全局计算，但只返回当前用户有权查看的文档，不泄露其他租户资料名称。

生产三个 app、每实例完整文档并发 4，因此正常同时推进 12 份文档。先完成的实例
会继续领取等待文档。

## 5. 文档状态

| 显示 | 含义 |
|---|---|
| 等待中 | 已持久入队，等待实例 |
| 处理中 | 主解析或任一启用衍生阶段运行 |
| 取消中 | 正在安全停止当前 generation |
| 删除中 | 正在跨存储清理 |
| 已完成 | 所有启用阶段成功且无未完成子任务 |
| 失败 | 主解析或任一启用衍生失败/降级 |
| 已取消 | 当前 generation 已取消 |
| 草稿 | 手工内容尚未发布 |

鼠标移到状态可查看：

- 主解析。
- 向量/关键词。
- VLM/ASR。
- 摘要。
- 问题/图谱。
- Wiki。

### 5.1 `none` 和跳过

- 文档等待或主解析处理中：`none` 显示“尚未开始/等待前置解析”。
- 功能关闭：显示“未启用”。
- 内容不适用或明确结构化跳过：显示“已跳过”。
- 执行异常：显示失败或降级。

“已跳过”必须能从阶段 span 的 `skipped` 状态或 `output.skipped` 原因得到证据。
合理例子是没有可抽取的 source chunk、空白/装饰性图片，或旧 generation 已被重建、
取消、删除 fencing。模型/解析器失败、超时、Neo4j/Wiki 写入失败、批次部分失败
都不是跳过；这类情况必须显示失败/降级并进入失败筛选。

### 5.2 状态筛选

“全部状态”可筛选：

```text
等待中 / 处理中 / 取消中 / 删除中 / 已完成 / 失败 / 已取消 / 草稿
```

筛选依据是完整工作流。主解析完成但 Wiki/图谱/问题失败的文档会进入“失败”。

## 6. 什么才算完成

一份启用了全部能力的文档只有同时满足以下条件才完成：

```text
parse_status = completed
pending_subtasks = 0
summary_status = completed
enrichment_status = completed
wiki_status = completed
chunk 和启用的 embedding 已持久化
实体图谱节点关系已写入
```

普通用户看卡片和悬停状态；管理员验收还要检查 PostgreSQL、向量、Neo4j、Wiki 和
对象存储。

## 7. 图片和音频

### 图片/扫描 PDF

1. 知识库开启多模态。
2. 选择支持视觉的 Qwen VLM 或其他兼容模型。
3. 上传图片或扫描 PDF。
4. 等待图片理解/OCR、chunk、向量和衍生任务完成。
5. 用图片中的已知内容做检索验证。

### 音频

1. 开启音频处理。
2. 选择平台下发的 Qwen2.5-Omni-7B；旧 Qwen ASR 1.7B 已下架。
3. 上传 MP3/WAV/M4A/FLAC/OGG 等。
4. 等待转写和后续索引。
5. 检查转写 chunk 和真实召回。

VLM/Omni 排队时显示等待/处理中，不显示跳过。

## 8. 大文件

### 8.1 上传

- 知识源原文件最大 2048 MiB。
- 入口为 2304 MiB。
- 单次 DocReader 传输仍为 50 MiB。
- 超大文档由系统拆分后作为一个逻辑文档发布。

### 8.2 预览

前端先请求 preview policy。典型原始预览上限：

| 类型 | 上限 |
|---|---:|
| PDF | 24 MiB |
| DOCX | 4 MiB |
| PPTX | 8 MiB |
| XLSX/CSV | 2 MiB |
| 常见图片 | 5 MiB |
| 常见音频 | 20 MiB |

文件体积、结构预检、是否物理拆分和 chunk 数都会影响结果。超过 240 chunks、
结构复杂或解码器无界时，界面显示分页解析内容或下载，不一次性载入浏览器。

移动端 PDF.js 的 worker、WASM、CMap、字体和 ICC 均由本站提供；复杂 JPX/JPEG2000
PDF 按页懒渲染。企业微信引用阅读页、知识库预览和解析分片都应验证，不能因文件较大
或私有图片需要鉴权而显示永久空白。

## 9. 预览、下载和时间线

- 预览：按 preview policy 使用原始预览或分页内容。
- 下载：下载原始文件，仍受知识库权限。
- 时间线：查看解析、拆分、向量、摘要、问题、图谱、Wiki 的耗时和错误。
- 队列位置：判断是等待容量还是阶段异常。

## 10. 重建、取消和删除

### 重建

- 创建新的 processing generation。
- 使用当前知识库或本次覆盖配置。
- 旧 generation 的迟到任务被 fencing。
- 重建后卡片立即进入新的状态/筛选桶。

### 取消

- 文档先进入“取消中”。
- 系统停止领取新子任务并等待在途执行收敛。
- 最终进入“已取消”，不能手工改数据库状态。

### 删除

等待中、解析中、衍生处理中和已完成文档都可以删除。系统会：

1. 隔离当前 generation。
2. 清除在途任务。
3. 删除 chunk、向量/关键词和问题。
4. 删除 Neo4j 文档范围图谱数据。
5. 清理 Wiki 来源和页面影响。
6. 删除对象存储中的原文/衍生对象。

只从列表消失不代表后端清理成功；专项验收会联合检查数据库、Neo4j、Wiki 和对象。

## 11. Wiki

Wiki 适合把大量资料组织为页面、目录和链接关系。

### 11.1 两类图

- Wiki 图：页面之间的入链/出链，存 PostgreSQL。
- 实体图：LLM 抽取的实体关系，存 Neo4j。

### 11.2 大规模图浏览

1. 节点列表按页面类型分类。
2. 搜索和列表服务端分页。
3. 初次只加载有界 overview。
4. 选择节点后展示“中心节点 + 一跳邻居 + 关系”。
5. 点击关联节点后，它成为新中心并加载自己的邻接图。
6. 邻居过多时分页，不无限累积整库图。

因此仍能查到每个节点并逐点探索关系，不会因全库节点过多卡死。

## 12. 检索问答

- 先确认目标知识库文档完整完成。
- 选择知识库、文档、标签或 @ 资源范围。
- 查看回答引用的文档/chunk/Wiki/Web/工具。
- 召回不准时优先检查资料、分块、TopK、阈值、Rerank 和索引。
- 不通过修改智能体提示词掩盖召回缺陷。
- 无证据时应明确没有足够资料。

## 13. 使用智能体

| 任务 | 推荐 |
|---|---|
| 制度/手册问答 | 快速问答 |
| Wiki 页面导航 | Wiki 问答 |
| 多步工具任务 | 智能推理 |
| 业务数据库 | 数据分析 |
| CSV/Excel | 表格分析 |
| 知识 + DB + MCP + Web | 通用智能体 |
| Word/Excel/PDF/PPT | 文档处理 |

Agent 产物在 terminal 前进入私有对象存储。用户从任意 app 下载时都要重新校验
tenant/session 权限。

## 14. 常见问题

### 有队列位置但很久没开始

文档已安全入队。管理员检查 waiting/active/capacity、实例健康、模型准入和
DocReader，而不是重新上传同一文档。

### 一个实例异常后没有立即转移

系统优先避免双执行。心跳超时之外还要等待租约、boot/epoch fencing 和精确终止
或节点隔离证明。

### 上传返回 413

检查 frontend/mobile、Ingress、ELB/WAF 每一层是否允许 2304 MiB；内部 Agent
代理至少 128 MiB。任一层仍为默认 1 MiB 都会提前失败。

### 图谱/Wiki 显示失败

检查具体阶段、模型、Neo4j 和 Wiki 队列。启用功能执行异常不能改成跳过。

### 其他测试知识库出错

只修复并重建对应测试知识库。不要删除或重新解析已经正常的“公司制度”知识库。

## 15. 管理员提示

- 生产每个 parse-worker 完整文档并发保持 4，三个副本合计 12。
- 集群模型准入是总量，不能乘 API/worker 副本数。
- 生产持久文件使用私有 OBS，不使用 RWX。
- 正常 app 使用 `AUTO_MIGRATE=false`；迁移由一个维护 app 执行。
- 多 API/worker/DocReader/Agent/Web 不代表 PostgreSQL、Neo4j、Redis 和外部
  llmgateway 已无单点。
