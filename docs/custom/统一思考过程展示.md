# 统一思考过程展示

桌面、移动端和嵌入聊天共用 `frontend/src/custom/modules/agentstream/ProcessPreview.vue`
和 `processPresentation.ts`。所有智能体沿用同一个 Agent Runtime 事件出口，不增加
LLM 调用，不要求模型调用额外的 thinking 工具，也不为展示补做检索。

## 展示规则

- 运行中最多三条模型已有的思考/说明片段、两条操作；长文本截断并限制行数。
- 不设运行中的“查看过程”按钮。检索结果本身可点击，展开时固定该行，另一行继续更新。
- 只显示实际返回的过程内容。没有模型过程文本时，以“正在思考”和真实操作状态展示。
- 查找资料、阅读文档、搜索网页、读取网页、分析数据、处理文件等按工具类别共用文案。
- 结果数量必须有依据：缺失或无法识别不等于零；只有明确的零结果才能显示“未找到”。
- 文档按知识 ID、网页按 URL、Wiki 按知识库和 slug 合并；片段数不是文档数。
- 文档标题、网页地址及片段在操作行内展开，复用 ContentPopup。每次加载十个来源，
  详情区域内部滚动；只展示本次工具实际返回的片段，不宣称已阅读全文。
- 结束后从原有检索数、调用数、耗时汇总行展开历史。失败与停止保留已发生的步骤。
- 检索结果与最终引用分别统计；分享模式不公开过程和私有检索结果。

## 事件和存储

Python 将供应商已提供的 ThinkingBlockDelta 按 block_id 合并；普通文本仅在本轮
确认为业务工具调用的前置说明时作为 commentary 发出。最终答案仍按原提交链路发布。
process_status 表示真实的模型调用或结果交付阶段，不计入推理轮数。

Go 使用 run ID、revision、事件类型和 block ID 标识过程片段；持久 Outbox 保留顺序，
ToolReceipt 确定工具结果。历史由这两者投影，保存在已有 agent_steps 中。
展示来源元数据在 `process_sources.go` 统一生成；SSE 仅携带数量和前两个来源身份，
展开后读取已有回执中的内容。该元数据不进入模型工具响应，不改变模型上下文预算。

## 来源详情 API

- 登录用户：`GET /api/v1/custom/agent-runtime/messages/:message_id/process/:call_id/sources`
- 嵌入渠道：`GET /api/v1/embed/:channel_id/sessions/:session_id/messages/:message_id/process/:call_id/sources`
- 查询参数：`offset`，默认 0；每页十个来源。
- 返回：`sources`、`total`、`next_offset`。来源含 `id/kind/title/url/knowledge_id/knowledge_base/snippets`。
- 登录路径校验租户、会话所有者和消息；嵌入路径校验渠道、会话签名和消息。无权或已删除返回 404/403。
