## 边界

保留各智能体类型和统一 AgentScope Harness。知识问答 15 次；启用产物的智能体 100 次；
未启用产物的其他类型 50 次。文件自动交付按 `enable_artifacts` 且非知识问答生效。实现不匹配
会话、问题、文档、模型名称或具体生成工具。

生成模型只负责执行任务和保存成品。发现、文件可用性校验、上传、幂等恢复、消息附件提交全部由代码执行，不调用 LLM，不追加答案纠正，不评价内容正确性或排版。生成流程中原有的检查保持原状，不作为发布阶段的新内容校验。

## 本轮产物判定

`/workspace/outputs` 是成品目录；输入、脚本、预览和缓存使用其他目录。文件生成途径可以是 Write、Edit、Bash、库调用或其他工具，交付不依赖某一种写入工具。

在模型执行前计算成品目录的路径与 SHA-256 基线，通过 `runs/baseline` 持久化至运行记录。基线首次建立后不覆盖；Worker 接管同一运行时沿用。每次用户请求使用独立的运行工作区。

交付时只选择新路径，或者相同路径但内容哈希发生变化的文件。仅修改时间变化、内容完全相同的文件不发布；原文件内容复制到新成品路径属于本轮新文件。输入目录、隐藏文件、隐藏目录、符号链接及非普通文件不参与产物收集。

## 唯一交付流程

1. SDK 返回最终候选答案或结束执行，Go 原子持久化候选答案/执行结果，将运行转为 `finalizing`。
2. `running` 的模型和业务工具准入不再成立。代码关闭执行容器以停止后台写入，再使用同一持久运行卷读取成品。
3. 对比原基线，读取本轮新增或修改的文件；读取内容必须与冻结后清单中的哈希一致。
4. 校验文件非空、大小限制及现有格式可用性。Office 校验 ZIP、关键 XML 和校验和，PDF 检查文件标记。校验通过的同一份字节直接上传；失败文件不发布，其他合格文件继续交付。
5. Go 沿用已有私有产物存储，验证运行、租户、会话、消息及当前 owner epoch，提交对象并核验大小、哈希。幂等文件令牌由运行、相对用途明确的完整成品路径及内容哈希生成。
6. 根据持久文件记录提交结构化产物列表，与消息和完成事件一同提交；正文不拼接下载链接，桌面、移动端和嵌入聊天在末尾显示专用产物卡片。IM 在发送边界将同一清单转为访问链接。模型有没有写文件路径或调用发布动作，不影响交付。
7. 终态提交后清理工作区。存储或控制链路暂时不可用时保留交付记录和源文件；Worker 接管后只继续交付，不初始化模型或重新生成文件。

每次交付尝试有独立的十分钟 I/O 窗口，超时后仍可由同一运行的交付状态恢复。模型的迭代次数、Token 和执行截止时间不用于阻止已有成品发布。执行期限耗尽的文件智能体会进入交付阶段；执行未完成与文件已成功交付可以同时成立，用户看到 `incomplete` 和已有下载。用户主动取消仍终止任务。

## 删除的冲突实现

- 模型工具目录中的 `publish_artifact` 及其专用工具回执分支。
- 从最终答案正文提取工作区路径来触发发布。
- 模型没声明文件发布就抛异常的兜底。
- 交付违规后要求模型再生成一遍答案的分支。
- 为提醒模型发布而临时扩大收尾迭代窗口的改动。

保留其他已经确认的修复：预算内部接口鉴权、文件连续编辑缓存、异常工具参数恢复及可重放的历史协议、共享预算、短暂 HTTP 故障的有界重试、源数据文件交接。它们不参与决定产物是否发布。

## 条件式产物展示提示

模型调用前仅当文件清单相对本轮基线存在新增路径或内容变化时，临时告知模型系统会在末尾展示通过文件检查的产物，正文简述结果即可。该提示不写入 SDK 历史；删除文件或恢复原内容后自动消失，普通问答不携带此提示，不增加模型请求。实际发布清单来自已提交运行结果，同时用于流式完成、历史回读和后续对话的交付事实。

展示链路不再伪造工具事件，也不从回答链接推断文件。只读取已提交的 completed/incomplete 运行；尚在上传或 finalizing 的文件不作为已交付产物展示。历史回读沿用会话鉴权和消息身份范围。

## 统一最终答案提交

所有智能体复用 AgentScope 的 `structured_schema` 和内置 `GenerateStructuredOutput`，只提交一个非空 `answer` 字段。每次决策通过协议选择业务工具或最终提交，最终提交必须独立于业务操作批次。自由正文不再作为答案候选；流式展示只解码最终提交的 `answer` 字段，最终保存仍以完整结构校验通过的提交为准。引用、Markdown 和 Unicode 保持原值，不做语言过滤、逐句删改或额外模型重写。

结构校验失败、没有提交或把结束提交与业务操作混在一轮时，直接进入现有未完成/失败收尾，不追加纠正生成。最终提交属于 SDK 内部结束协议，不进入业务工具记录，不初始化工作区，也不负责发布文件。文件仍由现有纯代码流程按本轮变更和可用性检查结果交付。

SDK 的结构化收尾预留仅为一次，包含在公开的 15/50/100 次上限内；预算末轮只允许最终提交，禁止新的业务操作。恢复时保留检查点中的回复身份、已用迭代数及已提交结果；已经完成的答案恢复无需再调用模型。旧的“无工具正文就是最终答案”分支已移除。

内部处理方法、执行路径及检查记录的展示约束合并在原有 `OutputPresentation` 中，只有本轮文件相对基线新增或修改时，附加到当前请求的最终 `answer` 字段说明。没有本轮文件变化、仅读取文件和普通问答不携带这段提示；不再另插系统消息，不修改 SDK 的原始 schema，也不写入持久历史。协议保证其他通道不会被当成答案提交，正文语义仍由上述动态约定约束。

正常决策保留 SDK 的自动工具选择，仅在预算末轮限定最终提交。实际模型对同一个已完成检查的上下文，在 `required` 下继续调用检查工具，而自动选择连续两次提交答案；因此没有保留每轮强制调用工具的实现。最终提交的工具说明明确“已可回答或不能完成时结束”，避免将结束机制描述成需要先收集资源的业务功能。
