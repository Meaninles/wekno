# 通用智能体多副本回调与生产验收

> 生产实施日期：2026-08-10
> 配置源码提交：`d283b368852adcceb9c0a5a55d7d48dccd4dba29`
> 适用环境：CCE `weknora` namespace，`weknora-app` 三副本

## 1. 问题与根因

通用智能体的活动运行记录保存在发起请求的 Go API 进程内。Python Agent 调用
`/api/v1/custom/general-agent/internal/tools/call` 时，只有创建该 run 的 API 进程
能够找到对应状态。

原生产配置把工具回调发往共享 `app` Service。三副本下，回调可能被转发到另外两个
API 进程，从而返回 HTTP 400，并出现 `run ... is not active`。这会表现为工具结果缺失、
召回异常或 Agent 回答与检索内容不一致。问题不在 Ingress、ELB、知识检索算法或模型
网关；共享 Service 对无进程亲和要求的普通 API 仍然正确。

## 2. 当前固定设计

API Pod 通过 Kubernetes Downward API 注入自身地址：

```yaml
- name: POD_IP
  valueFrom:
    fieldRef:
      fieldPath: status.podIP
- name: CUSTOM_GENERAL_AGENT_TOOL_CALLBACK_URL
  value: http://$(POD_IP):8080/api/v1/custom/general-agent/internal/tools/call
```

`POD_IP` 必须位于回调变量之前，才能由 kubelet 展开。每次 Agent run 因而形成：

```text
用户请求 -> 指定 API Pod 创建进程内 run
         -> Agent Service/Pod 执行
         -> 直接回调原 API PodIP:8080
```

`CUSTOM_GENERAL_AGENT_ARTIFACT_UPLOAD_URL` 仍指向共享 `app` Service。制品上传依赖
数据库和对象存储中的持久状态，不依赖某个 API 进程内的活动 run，不能机械地一起改成
PodIP。

Helm 有两层防回退：

- `helm/templates/validate.yaml` 拒绝把 Agent 工具回调改回共享 Service；
- `deploy/production/validate-rendered-manifest.py` 校验 `POD_IP=status.podIP`、变量顺序
  和回调地址。

Docker Compose 的三个 API 角色分别使用 `runtime-api-1/2/3` 回调地址，语义与生产
PodIP 方案相同。

## 3. 生产实施记录

本次只修改 `weknora-app` Deployment 的 Pod 模板：

1. 在工具回调变量之前增加 `POD_IP=status.podIP`；
2. 将工具回调从共享 Service 改为 `http://$(POD_IP):8080/...`；
3. 保持 app 镜像 digest、Service、Ingress、Agent Deployment、数据库和对象存储配置
   不变。

发布采用 `maxSurge=0/maxUnavailable=1`，三个 API Pod 逐个替换。完成后 Deployment
为 3/3 Ready、零重启，revision 为 33。

变更前清单、精确正向补丁、反向补丁、dry-run 结果和测试证据保存在生产运维机：

```text

```

目录权限为仅 root 可读写，`SHA256SUMS` 用于核对证据完整性。前一次因命令语法中止的
不完整目录没有用于发布；实际应用的是上述目录中通过 server dry-run 的

执行模式验收，不能套用普通 RAG 的断言。

## 5. 后续发布验收

每次涉及 app/Agent 配置或 API 副本数的发布至少检查：

1. 渲染清单通过 Helm lint 和 `validate-rendered-manifest.py`；
2. 每个 API 容器内 callback 恰好为自身 `status.podIP`；
3. 从所有 Agent Pod 到所有 API PodIP 的 `/health` 均为 200；
4. 对每个 API 副本定向执行至少一个真实工具调用；
5. callback 日志全部为 200，且没有 `run ... is not active`；
6. 快速问答、智能推理、通用智能体、文档处理和表格分析各完成一个符合资源现状的
   只读用例。

## 6. 回滚

本次没有镜像、数据库、Ingress 或持久数据变化。若仅回滚本配置，可在确认当前环境变量
顺序仍与备份一致后使用：

```bash
kubectl -n weknora patch deployment weknora-app \
  --type=json \
  --patch-file /root/weknora-agent-callback-backups/20260810T121054Z/callback-rollback-patch.json
kubectl -n weknora rollout status deployment/weknora-app --timeout=15m
```

反向补丁已经过 server dry-run。未来若 Deployment 环境变量发生其他改动，不能盲目
复用基于数组位置的 JSON Patch；应先重新读取 live Deployment 并核对索引。也可以在
确认 revision 32 只包含上一版 Pod 模板后执行受控 `rollout undo --to-revision=32`。
