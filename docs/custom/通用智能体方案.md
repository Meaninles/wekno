# 统一 Agent Runtime 实现说明

> 代码与配置核对日期：2026-09-13。本文基于当前工作区源码和配置，不是历史方案稿。
> 生产访问统一为 [https://knora.moutai.com.cn](https://knora.moutai.com.cn)，生产内部
> 节点、Service、模型网关、对象存储、工作目录和凭据不在本文公开。

## 1. 运行时覆盖范围

所有 Agent 问答通过 `internal/application/service/session_agent_runtime.go` 注册的单一
`AgentRuntime` 入口进入统一运行链路。`agent_mode` 的新配置值为 `agent`；能力由
`agent_type`、工具白名单、知识库/数据源范围、技能、MCP、联网、附件和产物开关共同决定。

当前类型为：

| `agent_type` | 主要能力 |
|---|---|
| `knowledge-qa` | 文档/FAQ 检索问答和引用 |
| `wiki-qa` | Wiki 页面、目录和来源阅读 |
| `hybrid-rag-wiki` | Wiki 导航与原文分块检索结合 |
| `data-analysis` | 已授权 MySQL/PostgreSQL 数据源的只读 SQL、统计和图表 |
| `table-analysis` | CSV/XLS/XLSX 文件的表格分析和图表 |
| `document-processing-agent` | Word、Excel、PDF、PPT 的处理和产物交付 |
| `general-agent` | 知识、Wiki、网页、MCP、技能、数据库和产物的组合任务 |
| `knowledge-base-manager` | 选定且有写权限的知识库文档管理 |
| `custom` | 手工组合提示词、工具和资源范围 |

`HasWorkspaceCapabilities` 当前对 `general-agent`、`data-analysis`、`table-analysis`、
`document-processing-agent` 和 `knowledge-base-manager` 开启工作区能力。知识问答是否
使用文件读取取决于当前附件和配置，不应把文件扩展名当作运行时分流规则。

## 2. 预算与配置

预算由 `internal/types/custom_agent.go` 的 `AgentIterationBudget` 统一规范化：

- `knowledge-qa` 固定 15 次迭代；
- 启用 `enable_artifacts` 时为 100 次迭代；
- 其他普通配置为 50 次迭代。

内置数据分析、表格分析、通用智能体和文档处理定义当前启用产物能力并使用 100 次迭代。
最终可用配置还会受模型、租户权限、请求范围、工具白名单和全局超时限制；客户端不能
通过请求体把服务端预算无限提高。

运行时配置由 `internal/application/service/session_agent_qa.go` 从智能体、租户、当前
请求和附件构建，包含：

- 模型、重排、视觉和语音模型选择；
- 知识库、知识文件、标签和 Wiki 检索范围；
- 网络搜索、网页抓取、FAQ 和检索阈值；
- MCP 服务选择、OAuth 等待和工具审批；
- 轻量技能、专业技能、数据库源和工具白名单；
- 多轮历史、检索历史、附件、图片、音频和文档模板；
- 产物能力、LLM 调用超时和运行时工作区约束。

## 3. Go 与 Python 的边界

`internal/custom/modules/agentruntime/` 负责创建持久 Run、解析配置、注册本轮工具、
检查租户/用户/权限、协调模型租约、保存事件和提交产物。`custom/services/agent-runtime/`
负责 AgentScope 运行循环、事件协议、预算协作、工作区和文件交付。

Python 运行时不直接连接 WeKnora 数据库、对象存储、MCP 或业务数据源。工具调用回到
Go 侧受控执行，Go 侧才是租户、权限、密钥、审计、来源和持久化边界。发送给运行时的
运行载荷会清除不应下发的模型/回调秘密；内部回调使用受保护的部署配置。

统一链路如下：

1. 会话 API 解析请求并确定当前智能体、租户和 Principal。
2. `BuildAgentRuntimeConfig` 解析类型预设、模型、知识库、附件、技能和本轮 @ 范围。
3. Agent Runtime 创建持久 Run，并为本轮生成带来源的工具注册表。
4. AgentScope 运行模型循环；业务工具通过受保护的 Go 回调执行。
5. Go 保存 thinking、工具、引用、答案、运行状态和产物事件，并向 Web、移动端、嵌入式
   或 IM 输出统一事件。
6. 运行结束后关闭模型/业务工具准入；产物阶段冻结写入、比较运行前哈希基线、校验并
   持久化，再提交消息附件。

## 4. 数据分析、表格和文档能力

- `data-analysis`、`general-agent` 和 `knowledge-base-manager` 可按权限注册数据库
  catalog/schema/query 工具；数据源列表由智能体配置和租户范围共同限制。
- `table-analysis` 使用表格 schema/analysis 工具处理知识库或本轮附件中的 CSV、XLS、XLSX，
  不使用 `db_data_sources`。
- `document-processing-agent` 使用文档模板、附件和产物能力；文件可用性、大小、类型、
  哈希和交付结果由代码校验，不靠模型回答路径推断产物。
- `knowledge-base-manager` 的新增、替换、删除工具还需要知识库写权限、当前 @ 范围和
  实时租户权限共同通过；替换是先新增后独立删除旧文档，不能把“已添加”当成“已解析完成”。

## 5. 文件、工作区与产物

- 输入文件、脚本、预览、缓存和最终产物分目录保存；运行工作区按任务隔离。
- 运行前建立路径和 SHA-256 基线，只收集本轮新增或内容发生变化且通过适用校验的普通文件。
- 最终产物先由运行时提交给 Go，Go 校验大小、哈希、类型和租户/运行归属，再写入受保护
  对象存储和数据库。
- 运行因模型超时、Worker 接管或网络中断而结束时，已提交产物与未完成状态分别保留；
  不能把中间文本、链接或工具路径直接当成已交付文件。
- 普通附件、DocReader、入口和内部产物代理使用不同大小上限，生产值见
  [当前生产实现与部署基线](./当前生产实现与部署基线.md)。

Kubernetes 生产工作区使用预绑定静态 PVC 和每运行独立 subPath，不动态创建或删除运行级
PVC，也不把对象存储挂成 POSIX 工作目录。具体 PVC 名称、挂载点、路径和节点属于受保护
部署数据。

## 6. MCP、技能和联网

- MCP 服务按 `all`、`selected`、`none` 选择；空的 selected 不退化为 all。
- MCP 的 URL 经过 SSRF 校验；凭据通过专用凭据流程、OAuth 和工具审批受控使用，不写入
  响应或运行日志。
- 轻量技能作为提示词/上下文能力注入；专业技能按技能包装载；预加载技能遵循渐进式披露
  和沙箱边界。三类技能的详细约定见 [Agent 技能文档](../agent-skills.md)。
- 网络搜索和网页抓取由 Go 侧 provider、凭据和 SSRF 策略执行，运行时不保存搜索密钥。

## 7. 对外接口

生产 API 基地址为 `https://knora.moutai.com.cn/api/v1`。常用 Agent 接口为：

- `POST /agent-chat/{session_id}`：SSE 流式 Agent 问答；
- `POST /sessions`：创建会话；
- `GET/POST/PUT/DELETE /agents`：智能体管理；
- `POST /custom/agent-runtime/runs/{operation}`：运行控制由当前受保护路由注册决定；
- `GET /custom/agent-runtime/artifacts/{id}/download`：产物下载；
- `GET /custom/answer-feedback/analytics` 及其 groups/options/detail 路由：反馈分析。

移动端使用同源 `https://knora.moutai.com.cn/mobile/`，嵌入式入口使用
`https://knora.moutai.com.cn/embed/{channel_id}`。本地开发/验收才使用 `http://localhost:5177`
和 `http://localhost:8080`；本地移动端同样使用 `/mobile/`，不使用 5178。

变更运行时代码后，至少验证：

1. 九种 `agent_type` 的创建、读取、运行、权限和预算；
2. knowledge/Wiki/hybrid 检索、引用、历史和多轮上下文；
3. 数据库只读 SQL、表格分析、文档模板和产物交付；
4. MCP selected/all/none、OAuth、审批和错误恢复；
5. 轻量/专业/预加载技能的配置与边界；
6. 图片、音频、附件、文件续改、超时、取消、接管和恢复；
7. API、移动端、嵌入式、IM 的统一事件、鉴权和跨租户隔离；
8. 三个生产 API、三个 parse、两个 derivative、两个 Wiki、两个 maintenance、三个
   DocReader 和两个 Agent Runtime 的角色化部署验收。
