# 常见问题

## 1. 如何查看日志？

```bash
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml logs -f runtime-api-1
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml logs -f runtime-parse-1
docker compose -f docker-compose.dev.yml logs -f postgres docreader
```

本地后端 API 来自 runtime profile 的 `runtime-api-1`，不是 `app` 或单体
`app-dev`。角色、实例数和启动顺序见[开发指南](../开发部署/开发指南.md)。

## 2. 如何启动和停止服务？

```bash
make dev-start DEV_ARGS="--minio --neo4j"  # 启动基础设施
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml up -d --force-recreate
```

停止本地后端角色：

```bash
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml down
```

后端代码修改后必须按[快速开发模式](../开发部署/快速开发模式.md)的顺序停止、构建
`runtime-api-1` 共享镜像并重新创建全部角色；基础设施需保持运行。不要使用
`start_all.sh`、`make dev-app` 或单体 `app-dev`。

> 开发模式下的启停参见 [开发指南](../开发部署/开发指南.md)

## 3. 服务启动后无法正常上传文档？

通常是 Embedding 模型和对话模型没有正确被设置导致。

### 排查步骤

1. 查看 `.env` 配置中的模型信息是否配置完整：

```bash
INIT_LLM_MODEL_NAME=your_llm_model
INIT_EMBEDDING_MODEL_NAME=your_embedding_model
INIT_EMBEDDING_MODEL_DIMENSION=your_embedding_model_dimension
INIT_EMBEDDING_MODEL_ID=your_embedding_model_id
```

2. 如果使用 remote API，还需提供 `BASE_URL` 和 `API_KEY`
3. 如需重排序功能，额外配置 Rerank 模型
4. 查看主服务日志，是否有 `ERROR` 日志输出

> 模型管理参见 [内置模型管理](../核心功能/内置模型管理.md)

## 4. 没有图片或者显示无效的图片链接？

1. 确认多模态功能已正确配置（知识库设置 → 高级设置 → 多模态功能）
2. 确认 MinIO 服务已启动
3. 检查 MinIO Bucket 权限
4. 配置 `MINIO_PUBLIC_ENDPOINT`（如需从其他设备访问）

**重要**：Bucket 名称不要包含特殊字符；如无法修改权限，可填入不存在的 bucket 名称，系统会自动创建。

## 5. 平台兼容性说明

`OCR_BACKEND=paddle` 在部分平台上可能无法正常运行。

- **方案一**：关闭 OCR 识别（删除 `OCR_BACKEND` 配置）
- **方案二**：使用外部 OCR 模型（推荐）— 配置 `OCR_BACKEND=vlm`

## 6. 如何使用数据分析功能？

当前有两条链路：

- 文件/知识库表格分析：上传或入库 CSV、Excel 等资料后，智能体通过知识库和数据分析工具处理已解析数据。
- 数据库数据源分析：在“数据源”中创建 MySQL/PostgreSQL 源，刷新元数据、启用表字段后绑定到智能体，运行时使用 `db_catalog`、`db_schema`、`db_query`。

数据分析智能体必须绑定至少一个数据库源；通用智能体和文档处理智能体可按需绑定。

### 注意事项

- 数据库源仅允许只读查询（SELECT、SHOW 等）。
- 复杂 Excel 解析失败时，可转成结构更清晰的 CSV 或拆分工作表后重新上传。

## 7. 页面里刚保存的配置几秒后又消失了？

通常是浏览器代理、缓存或插件干扰导致。建议：
1. 关闭浏览器代理和抓包工具
2. 强制刷新或使用无痕窗口
3. 检查 Network 面板确认请求未被代理改写

## 8. SSRF 校验白名单

`SSRF_WHITELIST` 配置项用于绕过常规 SSRF 限制，支持：精确域名、通配域名、IPv4/IPv6、CIDR。

```bash
# SSRF_WHITELIST=internal.service,*.corp.example,172.16.0.0/12
```

> 生产环境请谨慎配置。搜索引擎的 API 端点硬编码策略参见 [添加网络搜索引擎](../集成扩展/添加网络搜索引擎.md)

## 9. 文档排队、完整状态和筛选

- 有队列位置表示文档已持久接收，正在等待完整文档槽位。
- “已完成”要求主解析和启用的向量、多模态、摘要、问题/图谱、Wiki 都成功。
- `none` 在前置阶段未完成时是“尚未开始”，不是“已跳过”。
- 状态筛选使用 `workflow_status`；衍生失败也进入“失败”。
- 一个 app 心跳超时后不会仅凭超时立即接管，系统还需要 lease、boot/epoch 和
  精确终止/节点隔离证明。

## 10. IAM 同步出现“部分成功”怎么办？

IAM 组织人员同步会继续处理可读取的正常记录；如果单条人员记录格式异常且可以
隔离，运行结果会标记为 `partial_success`，并记录跳过数量。打开系统管理中的
同步运行详情即可查看跳过记录及其来源页、绝对位置、错误码和用户可读原因。

- 运行状态为 `failed` 时，通常是整页请求或不可恢复的同步错误，需先修复 IAM
  配置或上游接口后重新运行。
- `partial_success` 不代表所有人员都失败；无法关联的正常记录仍按新用户处理，
  其他可读取人员仍会正常关联已有用户。
- 定时同步默认关闭；启用后可选每日或工作日计划，默认运行时间为 03:10。也可
  手动执行全量同步，或选择组织及其后代组织同步。

## 11. 超大文件预览或上传失败

前端先使用 preview policy；大文件、复杂结构或超过 240 个 chunk 时展示分页解析
内容/下载，不直接加载原始 Blob。生产知识上传链路的 Nginx/Ingress/ELB/WAF 要
允许 2304 MiB、关闭 request buffering、设置 7200 秒超时；普通附件仍是 50 MiB
业务上限，内部 Agent 代理至少允许 128 MiB。

## 12. 大量 Wiki 节点导致图卡顿

不要加载整库全图。使用分类列表、服务端搜索和分页；初次加载有界 overview，
选择节点后只展示该节点及一跳邻居。点击任一关联节点会把它设为新中心继续加载，
邻居过多时分页。

## 13. 多实例和单点

app/DocReader/Agent/Web 多副本能解决执行层吞吐和单 Pod 故障，但 PostgreSQL、
Neo4j、LiteLLM 仍为单实例，Redis 当前没有自动切换，单 AZ 也仍是故障域。
详细边界见[当前实现架构](../../custom/当前实现架构与文档索引.md)。
