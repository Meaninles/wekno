# 开启知识图谱功能指南

本文说明如何启用并验证实体关系图谱（Neo4j）。Wiki 页面链接图的分类、搜索和
中心节点渐进浏览见[知识图谱与大规模关联浏览](./KnowledgeGraph.md)。

## 前置条件

- WeKnora 后端、前端、PostgreSQL、Redis 和模型服务可用。
- Neo4j 可从所有 app 副本访问。
- 用于实体/关系抽取的模型可用，并受集群级 Chat 准入保护。
- 生产已经配置 Neo4j 备份；当前单实例 Neo4j 仍是图谱功能单点。

## 开发环境

在 `.env` 配置：

```env
NEO4J_ENABLE=true
NEO4J_URI=bolt://neo4j:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_strong_password
# NEO4J_DATABASE=neo4j
```

启动并检查：

```bash
docker compose --profile neo4j up -d
docker compose ps neo4j
docker compose logs --tail=100 neo4j
```

修改运行配置后先停止旧 app，再重建受影响容器，避免旧实例继续使用旧环境。

## Kubernetes/生产

生产复用现有 Neo4j：

- app 使用内部 Service URI，例如 `bolt://neo4j.weknora.svc.cluster.local:7687`。
- 用户名和密码来自现有 Secret，不写入 values 或渲染产物。
- Network/安全组允许所有三个 app 节点访问 7687；7474 管理端口不对普通用户开放。
- 上线前后记录节点/关系基线和可恢复备份。

当前生产具体值和验证命令见
[当前版本生产更新部署执行手册](./custom/当前版本生产更新部署执行手册.md)。

## 知识库配置

1. 创建或打开文档知识库。
2. 在索引策略中启用知识图谱。
3. 启用实体/关系抽取，配置业务允许的实体类型和关系类型。
4. 选择有效的抽取模型。
5. 如需页面化知识，同时启用 Wiki；它与 Neo4j 实体图是两套数据。
6. 保存后上传一份具有已知实体关系的测试文档。

生产迁移或多实例验收不能通过关闭图谱来换取文档“完成”。

## 验证

### 文档工作流

等待文档卡片完整状态完成，悬停确认：

```text
主解析：完成
向量/关键词：完成（启用时）
问题/图谱：完成
Wiki：完成（启用时）
```

`enrichment_status=completed` 后还要确认相关批任务没有 pending/running。

### Neo4j

使用受限运维账号执行有界统计：

```cypher
MATCH (n)
RETURN labels(n), count(*) AS nodes
ORDER BY nodes DESC
LIMIT 50;

MATCH ()-[r]->()
RETURN type(r), count(*) AS relations
ORDER BY relations DESC
LIMIT 50;
```

再按当前 schema 的 tenant/knowledge_base/document 标识抽查新文档，不要只看全库
总数增加。

### 召回

使用明确依赖该关系的问题调用图谱查询/知识检索，核对返回节点、关系、chunk 和
来源引用。验收范围是召回质量，不通过修改智能体提示词掩盖检索问题。

### 删除和重建

- 重建后旧 generation 的图谱任务不能覆盖新 generation。
- 解析中删除要取消图谱任务并清理已经提交的文档范围关系。
- 已完成删除后，PostgreSQL 状态、Neo4j 和 Wiki 来源都不应残留该文档。

## 故障排查

| 现象 | 检查 |
|---|---|
| 无法连接 Neo4j | Service/Endpoint、DNS、7687 网络、Secret、TLS/数据库名、Neo4j 日志 |
| 文档一直处理中 | 队列位置、模型准入、图谱批任务、租约、Neo4j 写入 |
| 主解析完成但总状态失败 | `enrichment_status` 和失败批次；这是正确失败，不应改成跳过 |
| Neo4j 有数据但 Wiki 图为空 | 两类图不同；检查 Wiki 页面和页面链接 |
| 大图页面卡顿 | 确认使用 overview/ego、有界 limit、分类/搜索/分页 |
| 删除后残留 | 等待 deleting 终态，检查清理队列、Neo4j 和 Wiki 来源 |

启用成功的判据不是“Neo4j 容器在运行”，而是测试文档完整工作流、持久节点关系、
真实召回和删除生命周期都通过。
