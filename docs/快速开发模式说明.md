# 快速开发模式说明

> 本页描述当前本地开发编排，核对日期：2026-08-12。生产使用独立的多副本、OBS
> 和 RWO 临时卷，按[生产执行手册](./custom/当前版本生产更新部署执行手册.md)部署。

当前“快速”来自前端 Vite 热更新和后端共享 runtime 镜像的角色化重建流程。后端不
使用单体 `app-dev`，也不使用 `make dev-app`、`scripts/dev.sh app` 或额外的本地
Go 服务占用 `8080`。

## 使用方法

### 1. 启动基础设施

```bash
make dev-start DEV_ARGS="--minio --neo4j"
```

基础设施编排需要先达到可用状态：PostgreSQL、Redis、MinIO、Neo4j 和基础 DocReader
必须运行。向量数据库等其他依赖按 `.env` 的实际选择启用对应 profile。

### 2. 启动分角色后端

```bash
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml build runtime-api-1

docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml up -d --force-recreate
```

该编排包含 API 3 个、解析 2 个、衍生 2 个、Wiki 2 个、maintenance 2 个、一次性
migration 1 个、runtime DocReader 2 个及 API/DocReader 入口。浏览器和 API 分别从
`http://localhost:5177`、`http://localhost:8080` 访问。

### 3. 启动前端

```bash
cd frontend
npm ci
npm run dev -- --host 0.0.0.0 --port 5177
```

移动端固定访问 `http://localhost:5177/mobile/`，不使用 `5178` 端口。

## 后端代码修改

后端代码修改后必须先停止当前 runtime profile，再构建共享镜像并重建全部角色：

```bash
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml down

docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml build runtime-api-1

docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml up -d --force-recreate
```

仅修改前端时保留后端编排，重启占用 `5177` 的旧前端进程后重新执行 `npm run dev`。
仅修改 Markdown 不需要重建业务镜像，但仍应检查 `runtime-entry` 的 health。

## 角色与请求路径

```text
浏览器 :5177 ── /api、/files ──> runtime-entry :8080
                                      ├─ runtime-api-1
                                      ├─ runtime-api-2
                                      └─ runtime-api-3

runtime-parse-1/2 ──> runtime-docreader-entry ──> runtime-docreader-2/3
```

衍生、Wiki、maintenance 和 migration 角色共享同一个后端镜像，但通过
`WEKNORA_RUNTIME_ROLE` 执行各自职责。共享镜像构建入口固定使用
`runtime-api-1`，不代表只启动一个 API。

## 状态检查

```bash
docker compose -p weknora-runtime-profile-e2e \
  -f custom/tests/runtime_profile_e2e/docker-compose.yml ps

curl http://localhost:8080/health
```
